# 04_三段式作業模板（A／B／C）

> 每輪一份，共三輪（R1、R2、R3）。題目見 "04a／04b／04c 作業單"；本檔是格式與評分。
> A＝crossover 的「無 AI」題；B＝「有 AI」題；C＝驗證報告。
> 比重：A 手寫核心 40%｜B 指揮 AI 30%｜C 驗證報告 30%。
> 每一部分都要交，缺一不算完成。

## A｜手寫核心（無 AI，40%）

### 交付格式

| 欄位 | 內容 |
|---|---|
| 任務名稱 | |
| 給定的規格 | 抄下題目要求的規則 |
| 我的做法 | 步驟或程式碼（可手寫拍照） |
| 完成條件 | 怎麼知道做對了 |
| 用時 | 分鐘 |

### 規則

- 不得使用任何 AI。
- 可看講義與筆記。
- 不會的地方寫「卡在哪、會怎麼查」，可得部分分數。

## B｜指揮 AI（30%）

### 交付格式

| 欄位 | 內容 |
|---|---|
| 給 AI 的規格 | 你寫的規格（不是直接貼題目） |
| prompt 歷程 | 每則提問與回覆摘要 |
| token 截圖 | 檔名與用量 |
| 回合數 | 訊息數 |
| 採用／不採用 | AI 給的內容，哪些用了、哪些改了、為什麼 |
| 產出 | 程式碼或文件 |

### 規則

- 規格要自己寫，不能只說「幫我做」。
- 至少一則提問是「問為什麼」或「要求比較」，不是直接要答案。
- 截圖要含日期、模型、token 用量。

## C｜驗證報告（30%）

### 交付格式

| 欄位 | 內容 |
|---|---|
| 測試案例 | 表格：案例、預期、實際、通過與否 |
| 負向案例 | 至少兩個（錯誤輸入、邊界） |
| AI 錯在哪 | 至少兩個具體錯誤 |
| 我怎麼抓到 | 用什麼方法發現 |
| 修正 | 改了什麼 |
| 反思 | 下次會怎麼問 AI |

## 評分 rubric

| 部分 | 項目 | 分數 |
|---|---|---:|
| A | 正確性（符合規格） | 25 |
| A | 完整性（邊界、錯誤） | 15 |
| B | 規格品質（可執行、可驗收） | 12 |
| B | 歷程可追溯（prompt、token） | 10 |
| B | 採用判斷（說得出為什麼） | 8 |
| C | 測試完整（正向＋負向） | 12 |
| C | 錯誤分析（具體、可驗證） | 10 |
| C | 反思深度 | 8 |

## 三輪主題

| 輪 | A | B | C |
|---|---|---|---|
| R1 | 訂單狀態頁（無 AI） | 同型頁面（用 AI） | 六態與顯示規則的測試 |
| R2 | 介面契約（無 AI） | 同型契約（用 AI） | 契約測試與錯誤結構 |
| R3 | 一致性與權限規則（無 AI） | 同型規則（用 AI） | 整合驗收與反思 |
