# 作業單 R2｜介面契約

> 狀態代號：S1 草稿／S2 已下單／S3 已確認／S4 製作中／S5 製作完成（待店員確認）／S6 可取餐／S7 已取餐；SX1–SX4 為例外（缺貨／付款失敗／通知未送達／修改待確認）。

> 這一輪有 **A、B 兩題**（crossover：一題不用 AI、一題用 AI）與 **C 驗證報告**。
> 繳交到 Teams 作業區；檔名見最後一節。

## 0. 時間與規則

| 項目 | 規則 |
|---|---|
| A 題 | **不得使用 AI**；可看講義與筆記 |
| B 題 | 可用 AI；要存 prompt 歷程與 token 截圖 |
| 時間 | A、B 各一次做完；記錄開始與結束時間（不用截圖，填表即可） |
| 順序 | R1：先 A 後 B；R2：先 B 後 A（照輪次指示） |

## 1. A 題（無 AI，40%）

為「查詢取餐號碼」寫一份 REST 契約（不得使用 AI）：

1. 方法與路徑
2. 輸入參數（必填／選填）
3. 成功回應（欄位與型別）
4. 錯誤結構四欄：code／message／retryable／requestId
5. 防重複提交：同一個請求重送兩次，會發生什麼？

## 2. B 題（有 AI，30%）

同一題型，換一個資源（可用 AI）：為「櫃位指派」寫一份契約。

要求：

1. 先寫規格（端點、輸入、輸出、錯誤、冪等），再請 AI 產出。
2. 存 prompt 歷程與 token 截圖。
3. 標記採用／不採用。
4. 至少一則提問要求 AI 列出「你可能漏掉的邊界」。

## 3. C 驗證報告（30%）

| 欄位 | 內容 |
|---|---|
| 契約測試 | 至少 6 個案例（含 4xx／5xx） |
| 負向案例 | 缺欄位、型別錯、無權限、衝突 |
| AI 錯在哪 | 至少 2 個（例如漏 retryable、沒有冪等） |
| 怎麼抓到 | 你用什麼方法發現 |
| 修正 | 改了什麼 |
| 反思 | 下一次規格會多寫什麼 |
