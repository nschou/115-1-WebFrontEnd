# 作業單 R1｜訂單狀態頁

> 狀態代號：S1 草稿／S2 已下單／S3 已確認／S4 製作中／S5 製作完成（待店員確認）／S6 可取餐／S7 已取餐；SX1–SX4 為例外（缺貨／付款失敗／通知未送達／修改待確認）。

> 這一輪有 **A、B 兩題**（crossover：一題不用 AI、一題用 AI）與 **C 驗證報告**。
> 繳交到 Teams 作業區；檔名見最後一節。

## 0. 時間與規則

| 項目 | 規則 |
|---|---|
| A 題 | **不得使用 AI**；可看講義與筆記 |
| B 題 | 可用 AI；要存 prompt 歷程與 token 截圖 |
| 時間 | A、B 各一次做完；記錄開始與結束時間（不用截圖，填表即可） |
| 順序 | R1：先 A 後 B；R2：先 B 後 A（照輪次指示） |

## 1. A 題（無 AI，40%）

實作一頁「訂單狀態」，資料如下（不得使用 AI）：

| 欄位 | 值 |
|---|---|
| 訂單編號 | `#1042` |
| 目前狀態 | S5 製作完成（待店員確認）→ 可切換到 S6 可取餐 |
| 取餐號碼 | `A-1042` |
| 櫃位 | `3 號櫃` |

要求：

1. 依狀態顯示：**S6 才顯示取餐號碼與櫃位**；S5 之前不得顯示。
2. 畫面要有六態：default／loading／empty／error／success／interrupted。
3. 提供一個「切換到 S6」的按鈕，按下後畫面更新。
4. 說明：如果 S5 就顯示號碼，會發生什麼事（寫在頁面上）。

## 2. B 題（有 AI，30%）

同一題型，換一組資料（可用 AI）：

| 欄位 | 值 |
|---|---|
| 訂單編號 | `#2087`（內用） |
| 狀態 | S4 製作中 → S5 → S6 |
| 取餐號碼 | `B-2087` |
| 櫃位 | `1 號櫃` |

要求：

1. 先自己寫規格（狀態、顯示規則、錯誤處理），再請 AI 依規格實作。
2. 存下每一則提問與回覆摘要。
3. 標記 AI 給的內容：哪些採用、哪些改了、為什麼。
4. 至少一則提問是「問為什麼」或「要求比較」。

## 3. C 驗證報告（30%）

| 欄位 | 內容 |
|---|---|
| 測試案例 | 至少 5 個（含正向與負向） |
| 負向案例 | 至少 2 個（例如 S5 顯示號碼、S6 卻沒顯示） |
| AI 錯在哪 | 至少 2 個具體錯誤 |
| 怎麼抓到 | 你用什麼方法發現 |
| 修正 | 改了什麼 |
| 反思 | 下次會怎麼問 AI |
