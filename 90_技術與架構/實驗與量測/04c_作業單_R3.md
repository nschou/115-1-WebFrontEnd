# 作業單 R3｜一致性與權限（整合）

> 狀態代號：S1 草稿／S2 已下單／S3 已確認／S4 製作中／S5 製作完成（待店員確認）／S6 可取餐／S7 已取餐；SX1–SX4 為例外（缺貨／付款失敗／通知未送達／修改待確認）。

> 這一輪有 **A、B 兩題**（crossover：一題不用 AI、一題用 AI）與 **C 驗證報告**。
> 繳交到 Teams 作業區；檔名見最後一節。

## 0. 時間與規則

| 項目 | 規則 |
|---|---|
| A 題 | **不得使用 AI**；可看講義與筆記 |
| B 題 | 可用 AI；要存 prompt 歷程與 token 截圖 |
| 時間 | A、B 各一次做完；記錄開始與結束時間（不用截圖，填表即可） |
| 順序 | R1：先 A 後 B；R2：先 B 後 A（照輪次指示） |

## 1. A 題（無 AI，40%）

不看 AI，寫出兩條規則與一張矩陣（不得使用 AI）：

1. 付款冪等（idempotent）規則：同一個付款命令重送兩次，系統怎麼保證只扣一次？
2. 取餐號碼唯一規則：兩個店員同時發號，怎麼保證不撞號？
3. 權限矩陣：角色（顧客／店員／廚師／老闆）× 動作（建立訂單／確認接單／入櫃／修改菜單／取餐）。

## 2. B 題（有 AI，30%）

用 AI 產出同型規則，然後**審查**它：

1. 請 AI 產生付款冪等規則與號碼唯一規則。
2. 找出 AI 版本至少 2 個問題（例如沒有唯一約束、沒有交易邊界）。
3. 修正後寫出你的版本。
4. 存 prompt 歷程與 token 截圖。

## 3. C 驗證報告（30%）

| 欄位 | 內容 |
|---|---|
| 整合驗收 | 用前三輪的成果跑一次完整流程（下單→付款→製作→入櫃→取餐） |
| 測試案例 | 至少 8 個（含併發、重送、權限） |
| AI 錯在哪 | 至少 2 個 |
| 怎麼抓到 | 你用什麼方法發現 |
| 反思 | 這門課你最大的改變是什麼（100 字內） |
