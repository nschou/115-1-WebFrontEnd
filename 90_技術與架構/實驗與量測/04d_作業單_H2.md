# 作業單 H2：樣式策略與資料流

> 狀態代號：S1 草稿／S2 已下單／S3 已確認／S4 製作中／S5 製作完成（待店員確認）／S6 可取餐／S7 已取餐；SX1–SX4 為例外（缺貨／付款失敗／通知未送達／修改待確認）。

> 這一單元有 **A（無 AI）、B（有 AI）、C（驗證報告）** 三部分。
> 繳交到 Teams 作業區；檔名見最後一節。

## 1. A 題（無 AI，40%）

選一頁（例如訂單狀態頁），不使用 AI 完成：

1. 選一條樣式策略（工具優先／元件庫／設計系統），寫理由與一個代價。
2. 畫出這一頁的三條資料線：讀取、寫入、通知。
3. 指出這一頁哪一個狀態屬於「用戶端狀態」。
4. 找出一處寫死的顏色，改成設計變數（tokens）。

## 2. B 題（有 AI，30%）

同題型，換一頁（例如菜單頁），可用 AI：

1. 先自己寫規格（策略、三條資料線、狀態歸屬）。
2. 請 AI 依規格實作，存 prompt 歷程與 token 截圖。
3. 找出 AI 版本至少 2 個問題（例如把伺服器端狀態放進元件）。
4. 修正後寫出你的版本。

## 3. C 驗證報告（30%）

| 欄位 | 內容 |
|---|---|
| 三條資料線驗證 | 每一條都能指出起點與終點 |
| 狀態歸屬 | 至少 3 個狀態，標明伺服器端或用戶端 |
| AI 錯在哪 | 至少 2 個 |
| 怎麼抓到 | 用什麼方法 |
| 反思 | 下次會怎麼問 |
