# 05_量測表單（問卷、觀察、埋錯、prompt、token）

> 五份表單，對應計畫的 KPI。全部匿名編號（學號轉代碼）。

> 狀態代號：S1 草稿／S2 已下單／S3 已確認／S4 製作中／S5 製作完成（待店員確認）／S6 可取餐／S7 已取餐；SX1–SX4 為例外（缺貨／付款失敗／通知未送達／修改待確認）。完整定義見 `18_spec.md` §5。

## 0. 每週前測／後測（各 15 分鐘）

| 步驟 | 做什麼 |
|---|---|
| 1 | 開 `weeks.html`，選當週；或直接開 `quiz.html` |
| 2 | 輸入學號、姓名，開始作答 |
| 3 | 15 分鐘到或按交卷；後測可用 AI，交卷前截圖 token |
| 4 | 按「列印／另存 PDF」，存成 PDF |
| 5 | 上傳 Teams 作業區，檔名 `學號-前測-主題.pdf` |

> 每份測驗都是閉卷、不得使用 AI；分數由教師依「07_答案與評分規準」評分。

## 3. 埋錯測驗（T0、W15 各一次，同一份）

10 題，每題：指出錯在哪（1 分）＋說明怎麼修（1 分）。滿分 20。

| # | 埋的錯 | 正確答案要點 |
|---:|---|---|
| 1 | 顧客在 S5 就看到取餐號碼 | 顯示規則錯誤：S6 才顯示 |
| 2 | 廚師按完成就直接通知顧客 | 角色邊界錯誤：需店員確認入櫃 |
| 3 | 錯誤只回 500，沒有錯誤碼 | 無法判斷可否重試 |
| 4 | 付款沒有冪等（idempotent）鍵 | 重送會扣兩次 |
| 5 | 取號用「先查最大號再加一」 | 競態條件（race condition），應加唯一約束 |
| 6 | 前端隱藏按鈕就當成權限控管 | 直接打 API 就繞過 |
| 7 | 列表頁逐筆查明細 | N+1 查詢 |
| 8 | 顏色是唯一狀態提示 | 無障礙：狀態不只靠顏色 |
| 9 | 遷移直接改正式資料庫 | 無版本、無法回滾 |
| 10 | 快取沒有設定有效期 | 拿到過期資料 |

## 4. prompt 分類表（每輪）

把每則提問歸類，統計次數：

| 類別 | 定義 | 例子 |
|---|---|---|
| 直接要答案 | 只要求產出程式碼 | 「幫我寫這個頁面」 |
| 貼錯誤 | 貼錯誤訊息要求修 | 「這個錯誤怎麼修」 |
| 問為什麼 | 要求解釋原因 | 「為什麼要唯一約束」 |
| 要求比較 | 要求比較方案 | 「SSE 和輪詢差在哪」 |
| 要求測試 | 要求產生測試 | 「幫我想負向案例」 |
| 其他 | 不屬於上述 | |

> 指標：「問為什麼＋要求比較＋要求測試」÷ 總提問數＝蘇格拉底式比例。
