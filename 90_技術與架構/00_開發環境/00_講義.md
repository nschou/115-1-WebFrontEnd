# 第 0 講｜開發環境：Bun＋Next.js＋Prisma＋serverless 資料庫＋Tailwind

> 這一講不談架構，只談「讓程式跑起來」。
> 目標：每個人都能在自己的電腦上啟動專案、連上雲端資料庫、改一個畫面並看到結果。

## 0. 三個問題

1. 為什麼不能只用瀏覽器？為什麼要裝執行環境？
2. 這門課的最小工具集合是什麼？
3. 裝好了要怎麼證明「真的能用」？

## 1. 工具地圖

| 工具 | 角色 | 本課選擇 |
|---|---|---|
| **Bun** | 執行環境＋套件管理＋測試 | 主要 |
| **Node.js** | JavaScript 執行環境 | 備援（部分工具仍需） |
| **Next.js** | React 的應用框架（路由、伺服器端渲染） | 主要 |
| **Prisma** | ORM（物件關聯對映，把資料表變成程式物件） | 選做（看懂即可） |
| **Neon** | serverless PostgreSQL | 選做（看懂即可） |
| **Tailwind CSS** | 工具優先的樣式 | 主要 |
| **shadcn/ui** | 以 Tailwind 為基礎的元件原始碼集合 | 主要 |

> 全部都是「本機開發、雲端執行」：不需要 Docker，不需要自己架資料庫。

## 2. 為什麼是這套

| 決定 | 理由 | 代價 |
|---|---|---|
| Bun 取代 npm | 安裝快、指令少、內建測試 | 少數套件仍以 Node 為準 |
| Next.js | React 生態最完整、部署最直接 | 框架規則多，要先懂路由 |
| Prisma | schema 優先、型別完整 | 產生的查詢不易微調 |
| Neon | serverless Postgres、分支功能 | 冷啟動、連線要用 pooler |
| Tailwind＋shadcn | 樣式快、元件可改 | 需要設計變數約束 |

## 3. 五個階段

```text
① 裝 Bun（＋Node）
② 建 Next.js 專案
③ 接上 Neon（serverless Postgres）
④ 用 Prisma 建表與遷移
⑤ 裝 Tailwind／shadcn 並改一個畫面
```

## 4. 指令總表

| 目的 | 指令 |
|---|---|
| 安裝 Bun（Windows） | `powershell -c "irm bun.sh/install.ps1 | iex"` |
| 確認 Bun | `bun -v` |
| 建專案 | `bunx create-next-app@latest breakfast-app` |
| 啟動 | `bun run dev` |
| 加套件 | `bun add <套件>` |
| Prisma 初始化 | `bunx prisma init --datasource-provider postgresql` |
| 建表 | `bunx prisma migrate dev --name init` |
| 看資料 | `bunx prisma studio` |
| 加元件 | `bunx --bun shadcn@latest init` |

> 版本以官方最新為準；指令若變動，以官方文件為準。
>
> 裝完可跑 `check-env.ps1` 自我檢查（Bun／Node／Next／Tailwind／Prisma）。

## 5. 專案結構

| 路徑 | 放什麼 |
|---|---|
| `app/` | 頁面與路由 |
| `components/` | 元件（shadcn 會放這裡） |
| `prisma/schema.prisma` | 資料模型 |
| `prisma/migrations/` | 遷移紀錄 |
| `.env` | 連線字串（**不提交**） |
| `.env.example` | 範例（可提交） |

## 6. 環境變數與安全

| 規則 | 說明 |
|---|---|
| 連線字串只放 `.env` | 不寫進程式碼 |
| `.env` 不進 Git | 在 `.gitignore` 確認為忽略 |
| 給同學 `.env.example` | 只有欄位名稱，沒有值 |
| 前端不直接連資料庫 | 透過伺服器端程式 |

## 7. 常見錯誤

| 症狀 | 原因 | 處理 |
|---|---|---|
| `bun: command not found` | PATH 沒有 Bun | 重開終端機或重裝 |
| `Error: Port 3000 already in use` | 舊程序還在 | 關掉或換 port |
| Prisma 連不上 | 用到非 pooler 位址 | 改用 `-pooler` 連線字串 |
| Tailwind 樣式沒生效 | 沒引入 `@import "tailwindcss";` | 檢查 `globals.css` |
| `relation "X" does not exist` | 沒跑遷移 | `prisma migrate dev` |

## 8. TypeScript、Zod 與 gRPC

### 8.1 TypeScript：型別檢查

Next.js 專案建立時若選 TypeScript，已經有 `tsconfig.json`。要確認的是「嚴格模式」與「可以單獨檢查」：

```json
{ "compilerOptions": { "strict": true } }
```

```powershell
bunx tsc --noEmit
```

| 指令 | 用途 |
|---|---|
| `bunx tsc --noEmit` | 只檢查型別，不產生檔案 |
| `bun run build` | Next.js 建置時也會檢查 |

### 8.2 Zod：執行期驗證

```powershell
bun add zod
```

```ts
import { z } from "zod";
const OrderInput = z.object({ customer: z.string().min(1) });
type OrderInput = z.infer<typeof OrderInput>;
```

> TypeScript 管「編譯期」，Zod 管「執行期」；外部資料兩者都要。

### 8.3 gRPC：遠端程序呼叫框架

**後端入門**：gRPC 不是這門課的主介面（主介面是 REST），只要知道它與 REST 的差異與成本；差異整理在第 8 講。**瀏覽器不能直接說 gRPC**，需要 gRPC-Web 加一層 proxy。成本較高，因此列為**選做**。

| 路線 | 做法 | 適用 |
|---|---|---|
| 只用 Node／Bun 之間呼叫 | `@grpc/grpc-js`＋`@grpc/proto-loader` | 本機示範 |
| 產生型別 | `buf` 或 `protoc`＋`ts-proto` | 需要強型別 |
| 瀏覽器要用 | gRPC-Web＋Envoy proxy | 成本最高 |

```powershell
bun add @grpc/grpc-js @grpc/proto-loader
```

> 完整安裝與示範見 [01_附錄_gRPC環境.md](01_附錄_gRPC環境.md)。

## 9. 檢查點

> 沒有自己的專案時，用 [00_練習資料 使用說明](../00_練習資料/00_使用說明.md) 的示範系統完成本講檢查點。

1. 說出 Bun 與 Node 的差別，以及為什麼兩者都可能用到。
2. 用三個指令證明環境可用：`bun -v`、`node -v`、`bun run dev`。
3. 說明 `.env` 為什麼不能提交。
4. 指出「連得上資料庫」與「有資料表」是兩件事，各用什麼指令驗證。
