# 00_課程地圖｜資訊技術與架構（W11–W16）

> 定位：這門課以 **Web 前端**為主，但架構要能講清楚**全端**，否則學生無法做整體架構規劃。
> 對象：已完成 18_spec 的學生。上課與練習統一使用**示範參考版本**；作業與期末專案仍用學生自己的版本。
> 時數：W11–W16 共 6 週，每週 3 小時、**兩個主題**，合計 12 講。

## 1. 主題檢視：原本 8 項 × 補強

| # | 原主題 | 補強 | 風險 |
|---|---|---|---|
| 1 | client/server、HTTP/HTTPS | 請求生命週期、狀態碼語意、快取標頭、CORS、連線重用 | 只講名詞會變通識課 |
| 2 | HTML／CSS／JS | 渲染路徑、事件迴圈、阻塞資源 | 範圍太大，只挑會影響架構的 |
| 3 | CSS 框架（Tailwind、shadcn/ui、Astryx） | 先講**樣式策略三條路**：工具優先／元件庫／設計系統＋變數 | 三者不是同類；Astryx 仍是 Beta |
| 4 | 前端框架（React 與衍伸） | 伺服器端狀態 vs 用戶端狀態、渲染模式（CSR／SSR／SSG） | 只教 hooks 會變語法課 |
| 5 | TypeScript＋Zod | 編譯期 vs 執行期、結構定義當唯一事實 | 把 Zod 當 TS 的補充會失焦 |
| 6 | ORM（Prisma） | 對照 Drizzle（SQL 優先）、Kysely；ORM 邊界（N+1、遷移、交易） | 以為 ORM＝資料庫 |
| 7 | 資料庫（serverless） | 連線池、冷啟動、遷移、備份 | 不講連線池，上線第一天就爆 |
| 8 | RESTful／gRPC | gRPC-Web 在瀏覽器的成本、OpenAPI 契約、即時通道（SSE／WebSocket／輪詢） | 光 REST 做不到「1 秒一致」 |

## 5. 用語對照（台灣用語＋英文）

| 中文（台灣） | English | 說明 |
|---|---|---|
| 冪等 | idempotent | 同一個操作重送多次，只生效一次 |
| 競態條件 | race condition | 兩個動作同時改同一筆，結果取決於先後 |
| 一致性 | consistency | 多個地方看到的資料是否相同 |
| 交易 | transaction | 一組操作要嘛全成功、要嘛全失敗 |
| 唯一約束 | unique constraint | 資料庫層保證不重複 |
| 連線池 | connection pool | 重複使用資料庫連線，避免每次重連 |
| 冷啟動 | cold start | 服務久未使用，第一次請求較慢 |
| 身分驗證 | authentication | 你是誰 |
| 授權 | authorization | 你能做什麼 |
| 可觀測性 | observability | 從紀錄看出系統發生什麼事 |
| 結構定義 | schema | 資料欄位與型別的約定 |
| 遷移 | migration | 資料庫結構的版本化變更 |
| 伺服器端狀態 | server state | 真相在伺服器，前端只是快取 |
| 用戶端狀態 | client state | 只存在畫面的狀態（例如展開／收合） |
| 水合 | hydration | 伺服器渲染的畫面接上互動 |
| 伺服器端渲染 | SSR | 伺服器先產生 HTML |
| 靜態生成 | SSG | 建置時先產生 HTML |
| 端對端 | end-to-end | 從畫面到資料庫的完整路徑 |
| 決策矩陣 | decision matrix | 用一致的準則比較選項 |
| 取捨 | trade-off | 得到什麼、付出什麼 |

## 6. 教學策略

> **後端只到「看懂」**：ORM、資料庫、授權、交易與冪等，只要求「了解運作機制、說得出差異」，**不要求實作**；後續另有網站後端課程。**REST 與 gRPC 的差異列為必教**；Prisma／Neon 環境列選做。

| 原則 | 做法 |
|---|---|
| 每講一個可驗收產出 | 見第 3 節「可驗收產出」欄 |
| 用案例當練習 | 選型練習一律回到雲端早餐店 |
| 一主一輔 | 主講一個，另一套只講差異與代價 |
| 先問題再工具 | 講義用提問開場，不先給答案 |
| 手冊給步驟 | 每一步有「這樣算完成」 |

## 8. 選型章節的寫法

同類技術（REST／gRPC、SSE／WebSocket、Prisma／Drizzle、CSR／SSR）一律用同一張表，讓學生能比較：

| 欄位 | 要寫什麼 |
|---|---|
| 優點 | 這個方案強在哪 |
| 缺點 | 代價是什麼 |
| 常用情境 | 誰、什麼規模、什麼需求 |
| 不適合 | 什麼情況下不要用 |
| 決策順序 | 兩到三個是非題，導到答案 |

> 目標不是「介紹技術」，是讓學生**能選**：知道什麼時候不用它。
