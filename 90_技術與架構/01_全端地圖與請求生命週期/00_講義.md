# 第 1 講｜全端地圖與一次請求的生命週期

> 對應：W11 · 主題 1 · 可驗收產出：四層圖＋三個卡點
> 這一講只做一件事：把「使用者按下去到看到結果」之間的每一層攤開。

## 0. 三個問題

1. 在網址列輸入一個網址，到畫面出現，中間經過幾層？
2. 畫面轉圈很久，可能卡在哪一層？
3. 你在 spec 寫「狀態一變，1 秒內看到」，這 1 秒花在哪裡？

## 1. 全端地圖：四層

| 層 | 角色 | 它負責 | 失敗的樣子 |
|---|---|---|---|
| **用戶端**（client） | 瀏覽器 | 畫面、互動、發出請求 | 白畫面、按了沒反應 |
| **邊緣**（edge） | CDN／靜態主機 | 把檔案送到最近的節點 | 第一次載入很慢、拿到舊檔 |
| **伺服器**（server） | 應用服務 | 驗證、業務規則、組回應 | 500、逾時、重複扣款 |
| **資料層**（data） | 資料庫 | 保存與查詢 | 寫入衝突、連線用完 |

四層之間只有兩種動作：**請求（request）**與**回應（response）**。

## 2. 一次請求的八個步驟

| # | 步驟 | 花時間的地方 | 失敗的樣子 |
|---:|---|---|---|
| 1 | 解析網址、查 DNS | 第一次查詢 | 找不到網域 |
| 2 | 建立連線（TCP／TLS） | 握手 | 憑證錯誤、連不上 |
| 3 | 送出 HTTP 請求 | 上傳大小 | 請求過大被拒 |
| 4 | 伺服器路由與驗證 | 規則複雜度 | 401／403／400 |
| 5 | 業務邏輯 | 計算、外部服務 | 500、逾時 |
| 6 | 資料存取 | 查詢、鎖、連線 | 死鎖、連線池用完 |
| 7 | 組回應 | 序列化大小 | 回應過大 |
| 8 | 瀏覽器解析與渲染 | 資源數量 | 畫面卡住 |

> 練習：把「1 秒」拆到這八步。多數人會發現，問題不在伺服器，而在第 1、2、8 步。

## 3. HTTP 只要看四件事

| 看什麼 | 例子 | 判斷什麼 |
|---|---|---|
| 方法（method） | GET、POST、PATCH、DELETE | 這次是「讀」還是「改」 |
| 狀態碼（status code） | 200、201、400、401、403、404、409、500 | **誰的錯、能不能重試** |
| 標頭（headers） | Content-Type、Cache-Control、ETag、CORS | 格式、快取、跨來源 |
| 內容（body） | JSON | 資料本身 |

### 狀態碼的語意

| 類別 | 意思 | 前端該做什麼 |
|---|---|---|
| 2xx | 成功 | 更新畫面 |
| 3xx | 轉址 | 跟著走 |
| 4xx | **用戶端**的問題（參數錯、未授權、衝突） | 顯示原因，不要重試 |
| 5xx | **伺服器**的問題 | 可重試，但要有限次 |

> 409（衝突）在早餐店案例裡很常見：同一張單被兩個人同時改。

## 4. HTTPS 與 CORS

- **HTTPS**：TLS 握手＋憑證，保證「連到對的伺服器」與「內容沒被改」。本機可以用 http，上線一定要 https。
- **CORS**：這是**瀏覽器**的規則，不是伺服器在擋你。伺服器要回對應的標頭，瀏覽器才把回應交給程式。

## 5. 快取：三種，別混在一起

| 種類 | 在哪 | 控制方式 | 適合 |
|---|---|---|---|
| 瀏覽器快取 | 用戶端 | Cache-Control、ETag | 靜態檔、不常變的資料 |
| CDN 快取 | 邊緣 | 同上＋節點設定 | 圖片、CSS、JS |
| 應用層快取 | 伺服器 | 程式控制 | 常查但少變的資料 |

> 快取不是「有就好」：要先回答「這份資料可以舊幾秒」。

## 6. 回到你的 1 秒

| 拆分 | 你的系統大概花多少 | 怎麼量 |
|---|---|---|
| 網路（DNS＋TLS） | ? | 瀏覽器開發者工具 |
| 伺服器處理 | ? | 伺服器紀錄 |
| 資料存取 | ? | 查詢時間 |
| 渲染 | ? | 開發者工具 |

## 經典例子：一次「送出訂單」的八步

| 步驟 | 示例耗時 | 壞掉會看到什麼 |
|---|---:|---|
| DNS 查詢 | 20 ms | 轉圈很久才開始 |
| TLS 握手 | 60 ms | 憑證錯誤、連不上 |
| 送請求 | 80 ms | 逾時、重送 |
| 伺服器排隊 | 5 ms | 尖峰時變慢 |
| 業務規則 | 40 ms | 400／409 |
| 資料庫 | 30 ms | 500、鎖等待 |
| 回回應 | 20 ms | 回應很大、很慢 |
| 瀏覽器渲染 | 120 ms | 白畫面、卡頓 |

> 示例合計約 375 ms。**同一個「慢」，八步各有不同的修法**：加索引、加快取、減少請求、延後載入。

3. 針對你的系統，寫出三個最可能卡住的位置與量測方法。
4. 把 spec 的「1 秒」拆成網路／伺服器／資料／渲染四段，各給一個估計值。
