# 11 欄位命名規則（v1.0 定案）

> 2026-10-26 定案。三個爭議點已拍板：**取餐號碼**（非取餐碼）、**狀態用英文代碼**（UX 顯示中文）、**統一為櫃位**（`locker_no`）。
> 用途：UX.md、線框、`spec.md`、API 三邊的**唯一命名依據**。

---

## 一、三層命名，各司其職

| 層 | 用什麼 | 例子 | 誰看 |
|---|---|---|---|
| **UX.md / 線框** | **中文業務名** | 訂單編號、取餐時段 | 老闆、業務、設計 |
| **UI 文案** | 中文口語（可不同） | 「你的取餐號碼」 | 使用者 |
| **spec / API / 程式** | **英文 snake_case** | `order_id`、`pickup_slot` | 工程、AI |

**關鍵原則：UI 文案 ≠ 欄位名。**
文案可以口語、可以長（「你的餐點正在做，預計 8:25 好」）；欄位名必須穩定、唯一、可被程式引用。

---

## 二、五條規則

1. **中文名以 baseline 的「受詞」為準**（Blueprint 動作的對象），不要重新發明。
2. **英文用 snake_case，不用縮寫**，除非業界通用（`id`、`url`、`eta`）。
3. **同義詞只留一個**：取餐號碼／取餐碼／號碼 → 一律「取餐號碼」。
4. **布林用 `is_` / `has_` 開頭**：`is_paid`、`has_remark`。
5. **時間欄位標明語意**：`pickup_at`（時間點）／`elapsed_seconds`（時長）／`created_at`（建立時刻）。

---

## 三、狀態代碼（定案）

**UX 顯示中文，spec 用英文代碼。** 不對外顯示英文代碼。

| 代碼 | 中文顯示 | 說明 |
|---|---|---|
| `S1_DRAFT` | 未送出 | 購物車草稿 |
| `S2_RECEIVED` | 已下單 | 顧客送出 |
| `S3_CONFIRMED` | 已確認 | 店員確認內容 |
| `S4_PREPARING` | 製作中 | 廚師開始 |
| `S5_READY` | 製作完成 | 待店員確認（**不上看板**） |
| `S6_READY_FOR_PICKUP` | 可取餐 | 已入櫃 |
| `S7_PICKED_UP` | 已取餐 | 交付完成 |
| `SX1_UNAVAILABLE` | 缺貨 | 需換品項 |
| `SX2_PAYMENT_FAILED` | 付款失敗 | 可重試 |
| `SX3_NOTIFY_FAILED` | 通知未送達 | 降級看板 |
| `SX4_MODIFICATION` | 修改要求 | 製作前可改 |

## 五、怎麼用（給四個角色）

| 角色 | 動作 |
|---|---|
| 學生做線框 | 標**中文名**（訂單編號），不要標英文 |
| 寫 spec.md | 用**英文名**，並在表格附「中文名」一欄對照 |
| 寫 API | 請求出入口一律**英文名**，不得用中文 key |
| 寫 UI 文案 | 自由，但**不得改變欄位語意**（「取餐號碼」可以寫成「你的號碼」，但不能寫成「訂單編號」） |

---

## 六、驗收（可 lint）

| 檢查 | 標準 |
|---|---|
| 同義詞 | 全文搜「取餐碼／格號」應為 **0 筆** |
| 命名一致性 | 線框與 spec 的中文名 100% 對得上 |
| 布林前綴 | 所有 bool 欄位以 `is_`／`has_` 開頭 |
| 時間語意 | `_at` 為時間點、`_seconds` 為時長，不得混用 |
