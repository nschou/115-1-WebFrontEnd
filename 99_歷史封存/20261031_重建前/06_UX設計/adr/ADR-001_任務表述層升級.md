# ADR-001 任務表述層升級：七格任務句、設施替代、US 兩段式、SCR 三件套

| 欄位 | 內容 |
|---|---|
| 編號 | ADR-001 |
| 狀態 | **已採用**（2026-10-28 確認） |
| 日期 | 2026-10-28 |
| 提出者 | AI（在與教師討論任務句表述時提出） |
| 決策者 | 課程教師 |
| 受影響者 | 修課學生、後續使用此教材的助教 |
| 取代 | 第 5 週 §五／§八 的任務表述（三欄式） |

## 背景

第 5 週以「角色／工作事項／對象」三欄描述 Blueprint 任務，第 6 週據此推導 UX。實際推導時出現四個「推不下去」的現象：

| # | 現象 | 證據 |
|---|---|---|
| 1 | 畫面找不到任務來源 | `scr-05` 等頁面 README 寫「承接任務 T5、T6」，但 **T5／T6 從未被定義** |
| 2 | 任務句混進介面語言 | 「顧客在菜單頁按下送出」——這是設計結果，不是需求 |
| 3 | 設施沒有出處 | 看板、取餐櫃只被列為「執行者」，沒寫它替代了誰 |
| 4 | US 位置不明 | 先寫故事對不上畫面；先畫線框又沒有任務支撐 |

## 驅動因素

- 「畫面必須被任務召喚」——沒有任務支撐的畫面應刪除（來源：主線與閘門 G7）
- 需求層不得含介面詞（來源：業務語言測試、店長測試）
- 設施是角色替代，驗收基準為被替代的人際互動（來源：自助繳款機案例）
- 現有 23 條 AC、11 個畫面、21 個動作皆已可驗，不宜全部重做

## 考慮過的選項

| 選項 | 優點 | 缺點 | 為什麼不選 |
|---|---|---|---|
| A. 只補文件，不動表述 | 成本最低，學生不必重寫 | 漏洞留著：任務句仍含介面詞、設施仍無出處，下屆一樣會錯 | — |
| B. 整份 Blueprint 重做 | 最徹底 | 市場／Persona／CJM／決策都沒問題，重做是浪費，且會摧毀學生已完成的工作 | — |
| **C. 只回滾「表述層」** | 直擊病灶；上游不動、風格不動；改完可用 lint 檢查 | 學生要重寫任務表；教師要重講一節 | **採用** |

## 決定

採 C。把 Blueprint 的任務表述從三欄升級為**七格任務句**，並連帶修正三處：

1. **任務句七格**：前置業務狀態／A／業務動作／物件 z／狀態轉換 s1→s2／B／B 的決策；**禁用介面詞**（頁、畫面、按鈕、點選…）。
2. **設施＝角色替代**：每個設施標 `serves`（服務誰）／`substitutes`（替代誰）／`via`（透過誰）；驗收基準＝被替代的那段人際互動。
3. **US 兩段式**：US-B（業務版，線框前，確認值得做）＋ US-I（介面版，線框後，可走、有 AC），同編號兩個版本。
4. **SCR 三件套**：資訊規格（元素表：用途／資料來源／建議型態／型態依據）＋ 線框（HTML）＋ 樣式（tokens）。
> **後續分層**：ADR-005 將這個兩段式決策細化為「服務需求索引／US-B → UX／SCR → US-I／AC → spec.md」的階段契約；本 ADR 保留角色任務與 Story 分層的基礎原則。

推導順序固定為：

```
任務句 → US-B → 視圖矩陣 → 資訊流 → 頁面清單 → 線框 → US-I ＋ AC → 驗證
```

## 代價與風險

- **學生會覺得「又在改」**：以 §1.6 與 `18_推導修正的思考軌跡` 說明這是「推導不出來才回滾」，並提供「不變清單（8 件）」降低焦慮。
- **教師要重講一節**：第 6 週 §3 的順序要重排。
- **文件一致性風險**：舊的三欄任務表若不同步更新，會出現兩套表述 → 以 derive-check 的 lint 強制。

## 如何回滾

若七格任務句在課堂上證明太重（學生寫不出「狀態轉換」這一格）：

1. 降級為**五格**（前置狀態／A／動作／物件／B），把 s1→s2 與 B 的決策移到決策表；
2. 保留「禁用介面詞」與「設施替代」兩條（這兩條成本低、效果最大）；
3. 在本檔案加註「部分回滾」，不刪原文。

**第一次跑檢查就抓到 4 個「按鈕沒有出處」**（retry-menu／switch-category／back-to-menu／locker-clear），
其中 3 個屬於「復原動作」——進一步暴露模型缺口：**復原動作不屬於業務任務**。
處理方式：加 `recovery: true` 標記，免回指任務，但仍須有對應動作。

**追加（2026-10-28）**：操作元素補「後果四欄」（狀態改變／去處／回饋／失敗去處），
並把線框來源從一個（元素群）擴為三個（元素群／邊的終點／例外）。
檢查新增三條，第一次跑抓到 3 個孤兒線框（店員台、KDS、取餐櫃面板）——它們是非介面入口。
