# ADR-003 還原命名：SCR 是複合體，線框只是零件

| 欄位 | 內容 |
|---|---|
| 編號 | ADR-003 |
| 狀態 | **已採用**（2026-10-28） |
| 提出者 | 課程教師（指出「線框＝規格＋線框＋tokens」是循環定義） |
| 決策者 | 課程教師 |
| 受影響者 | 修課學生、助教 |
| 取代 | **ADR-002**（SCR→WIRE 全域改名） |
| 相關 | ADR-001（SCR ＝ 規格＋線框＋tokens） |

## 背景

ADR-002 把複合體從 `SCR-xx` 改名為 `WIRE-xx`，理由是「SCR 字面是螢幕，不精確」。
但這個改名犯了更嚴重的概念錯誤：

> **用「線框」去命名一個包含「線框」的複合體** → 循環定義：
> 「線框 ＝ 資訊規格 ＋ 線框 ＋ tokens」。

正確的層次是：

```
元件層：  資訊規格      線框        tokens
              ↓           ↓            ↓
組合層：        SCR（螢幕）＝ 三者合成
```

因此 `WIRE` 只配當**零件名**，不能當**整體名**。

## 驅動因素

- 定義必須能「先產出元件，再組合成 SCR」——SCR 是**結果**，不是起點
- 學生要能回答「SCR ＝ ？＋？＋？」，答案必須是三個**元件**，而不是「線框＋線框＋…」
- 容器（頁面／分步／彈窗／區塊）是另一個軸：只要有「規格＋線框＋tokens」，就是一個 SCR

## 考慮過的選項

| 選項 | 優點 | 缺點 | 為什麼不選 |
|---|---|---|---|
| A. 保留 WIRE，改成「WIRE ＝ 規格＋**線框元件**＋tokens」 | 不必再改名 | 中文仍會混用：一份文件裡「線框」同時指零件與整體 | 概念債還在 |
| **B. 還原 SCR 為複合體，WIRE 只作零件名** | 定義乾淨；與 ADR-001 一致 | 再一次全域改名 | **採用** |
| C. 兩個名字並存（SCR＝WIRE） | 零成本 | 學生永遠不知道該用哪個 | 最糟 |

## 決定

採 B：

| 名稱 | 指什麼 | 是否帶編號 |
|---|---|---|
| **SCR-xx** | 複合體（資訊規格＋線框＋tokens） | 是 |
| 資訊規格 | 元素表、六態、互動、文案 | 否（附屬於 SCR） |
| **線框（wireframe）** | HTML 結構與版面 | 否（說「SCR-05 的線框」） |
| **tokens** | 顏色／字級／間距／圓角 | 否 |

資料夾回到 `scr-NN-*`；編號回到 `SCR-NN`；`WIRE` 只保留在「線框」這個概念上，不帶編號。

## 代價與風險

- 短期內文件會出現「SCR 是螢幕」的舊印象 → 以 §3.5 的定義與本 ADR 校正。
- 兩次改名（ADR-002 → ADR-003）對學生是負面示範？**相反**：這是「決策可以被推翻並留下紀錄」的示範，ADR-002 不刪除。

## 如何回滾

若日後又認為 SCR 不精確：**不要再整體改名**，而是改「中文用語」或加「別名說明」。
因為兩次改名證明：改名成本高，但概念錯更貴。
