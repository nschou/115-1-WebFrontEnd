# 附錄 B｜三章 Prompt 骨架與審計清單

> 用法：把【】內換成你的檔案，整段貼給 AI（Claude／omp／任一模型）。
> 三份 Prompt 都有同一個「共同前綴」，先貼前綴再貼任務。

---

## B-0 共同前綴（三份都要）

```
你是服務設計師的設計文件助手。只能根據我提供的檔案作答，不得補充外部資訊。
每一列都必須附「來源定位」＝章節名稱 ＋ 逐字引用的原文片段（不得改寫）。
找不到來源就寫「無來源，待補」，絕對不得編造。
若某條是設計聯想（而非文件事實），請標為「設計推導」。
最後列出「你認為最不確定的 3 條」及原因。
```

---

## B-1 第 1 章：設計理由

```
輸入：
- @service-design-baseline.md（第 4、7、8 章）
- Design.md 第 2–8 章（Stitch 已產生的視覺參數）

任務：產生 Design.md 第 1 章「設計理由」。

輸出（嚴格照下列結構，缺一項視為未完成）：

1.1 風格一句話定義（≤25 字）：〔人格〕×〔情緒〕×〔節奏〕
1.2 品牌人格表：形容詞｜視覺對應｜型別（定律/慣例）｜反面案例｜來源
1.3 核心體驗目標表：目標｜放大什麼｜避免什麼｜來源
1.4 服務承諾表：CJM 階段｜承諾句｜來源（Blueprint 前台原文）
1.5 情緒需求優先序表 ＋ 不可違反限制清單

規則：
- 1.2 的每一列，視覺對應只能引用第 2–8 章「已存在」的值；找不到就寫「缺少對應，需調整風格」。
- 型別標「慣例」的必須給一個反面案例；標「定律」的必須給出處（如 WCAG）。
- 本章不得出現 hex、px、字體名稱（那是第 2–8 章的事）。
- 1.2 的形容詞必須是「可操作」的：能回答「那在畫面上是什麼」。
  若你寫出「高級」「有質感」這類無法操作的詞，請自行替換並說明替換理由。
```

## B-2 第 9 章：動效原則

```
輸入：
- @service-design-baseline.md（第 5 章角色交接、第 7 章 CJM 使用情境與情緒）
- Design.md 第 1 章（風格定義與情緒需求）

任務：產生第 9 章「動效原則」。

輸出：
9.1 檔位選擇：快 150ms／中 200–250ms／慢 300ms，選一檔並引用第 1 章的哪一句作為理由
9.2 動效清單表：觸發點｜目的（回饋/引導/狀態說明/裝飾）｜時長｜緩動｜reduced-motion 降級
9.3 禁止清單
9.4 不做動效的地方

規則：
- 時長只能從 9.1 的四個值裡選，不得自創。
- 目的填「裝飾」的，降級欄一律寫「全關」。
- 每個動效都要能回答「它幫使用者理解什麼」；回答不出來的請自行刪除，並列出你刪了哪幾條。
```

## B-3 第 10 章：回溯表與可替換性契約

```
輸入：
- Design.md 第 1–9 章全文
- @service-design-baseline.md（第 5–8 章，含 11 項決策 SD-01~SD-11）

任務：產生第 10 章。

輸出：
10.1 回溯表：決策（不是參數值）｜依據｜回溯到（章節）｜驗證狀態｜可替換性（底座/風格/連動）
10.2 覆蓋率報告：N（第 2–8 章 token 數）｜M（已回溯條目數）｜覆蓋率｜未覆蓋清單
10.3 換版程序

規則：
- 一條決策可以群組多個 token（如「冷色基底」群組 12 個 surface 色），但必須列出被群組的 token 名稱。
- 驗證狀態只有三種：已驗證（有實測）／設計推導（有依據未測）／待驗證（AI 推測）。
  沒有實測證據不得標「已驗證」。
- 標「底座」的條目必須說明「換了會破壞什麼」。
- 沿用 baseline 的決策代碼 SD-01~SD-11，不重新編號。
```

## B-4 三張審計清單

### 通用五條（每章都跑）

| # | 動作 | 通過標準 |
|---|---|---|
| 1 | 來源抽查：抽 5 條，Ctrl+F 找原文 | 100% 命中 |
| 2 | 矛盾掃描：跨章有沒有打架 | 0 |
| 3 | 對應完整性：1.2 的形容詞在 2–8 章有值 | 全部有 |
| 4 | 反面檢查：慣例都有反例嗎 | 全部有 |
| 5 | 誠實度：待驗證有沒有被寫成已驗證 | 100% 誠實（全審） |

### 第 1 章專屬

| # | 檢查 | 常見錯誤 |
|---|---|---|
| 1 | 有沒有出現 hex／px／字體名 | AI 會偷塞 `#134E4A`，要刪 |
| 2 | 形容詞可不可操作 | 「高級」「有質感」= 空話 |
| 3 | 能不能脫離 baseline 單獨讀 | 出現「見上一份文件」= 不合格 |
| 4 | 服務承諾是否逐階段齊全 | 常漏「取餐」階段 |

### 第 9 章專屬

| # | 檢查 | 常見錯誤 |
|---|---|---|
| 1 | 時長是否都在 9.1 的四個值內 | AI 常自創 180ms |
| 2 | 每個動效有沒有「目的」 | 空白的就刪 |
| 3 | 「裝飾」項是否全關 | 常只寫「縮短」 |
| 4 | 與第 1 章節奏是否一致 | 「俐落」卻寫 300ms = 矛盾 |

### 第 10 章專屬

| # | 檢查 | 常見錯誤 |
|---|---|---|
| 1 | 覆蓋率 ≥80% | 只列 12 條卻有 48 個 token |
| 2 | 「已驗證」有沒有實測證據 | 沒測過就標已驗證 = 造假 |
| 3 | 底座條目有沒有寫「破壞什麼」 | 只寫「不可換」不寫後果 |
| 4 | SD 代碼有沒有沿用 | 重新編號 = 斷鏈 |

## B-5 抽樣與處置

| 類別 | 比例 | 處置 |
|---|---|---|
| 定律／不可換 | 100% | 發現問題 → 修正後重跑 |
| 待驗證 | 100% | 造假 → 整章退回 |
| AI 自陳 3 條 | 100% | 三選一表態（採用／修正／剔除＋理由） |
| 慣例／可換 | 30% | 發現問題 → 記錄不退回 |
