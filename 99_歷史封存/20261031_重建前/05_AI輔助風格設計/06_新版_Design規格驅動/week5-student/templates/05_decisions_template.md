### 4. 操作流程

#### KDS 操作流程與訂單狀態流

```
接收(Received) → 製作中(Preparing) → 完成(Ready)
```

1. 訂單自動傳送到 KDS 螢幕
2. KDS 依路由規則分派品項到工作站
3. 廚師確認接收 → 開始製作 → 完成
4. 計時器顏色提醒 urgency（綠→黃→紅）
5. KDS 通知店員「訂單完成」
6. 店員確認餐點備妥 → 放置取餐櫃 → 取餐櫃通知顧客

關鍵區分：「廚師完成」≠「店員確認可領取」

#### 預估取餐時間三層次

| 層次 | 機制 | 準確度 | 導入條件 |
|---|---|---|---|
| 基本版 | 固定值，店員可調整 | 依賴人工 | 無 |
| 規則版 | 品項標準時間 + 佇列計算 | 中等 | 需設定標準時間 |
| AI 版 | ML 模型動態預估 | 較高 | 需 KDS 歷史數據 |

#### 缺貨同步機制

| 環節 | 誰做 | 怎麼做 |
|---|---|---|
| 發現缺貨 | 廚師或店員 | 通知老闆 |
| 停止供應 | 老闆（或POS庫存連動） | 數位菜單標記缺貨 |
| 恢復供應 | 老闆 | 確認補貨後恢復 |
| 已下單缺貨 | 店員 | 通知顧客更換品項 |

#### POS 與庫存時序

```
階段1：POS 上線記錄銷售
階段2：設定食譜配方自動扣庫存
階段3：低庫存門檻提醒
階段4(未來)：AI 庫存預測
```

### 兩個可 lint 的檢查

| 指標 | 公式 | 標準 |
|---|---|---|
| 物件覆蓋率 | 被至少一項決策引用的物件 ÷ 物件總數 | 100% |
| 無依據決策率 | 沒引用「人」也沒引用「物」的決策 ÷ 決策總數 | 0 |

> 寫法紀律：必須指到「屬性」。寫「受菜單影響」不合格，要寫「菜單品項.照片必填且會過期」。
