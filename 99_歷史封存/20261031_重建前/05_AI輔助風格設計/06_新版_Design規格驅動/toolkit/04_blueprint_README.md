## 調研方法（從第 4 週講義抽取）

### 步驟 1：從 CJM 接續前台行為
CJM 的每個階段都有前台行為（顧客做什麼）。Blueprint 從這裡接續，推導後台需要做什麼。

### 步驟 2：用角色填後台行為
從 Persona（02_persona.md）推導誰來做後台工作。用「角色+動作」描述，不用系統功能名稱。包含設施角色（取餐櫃、店內看板）——它們是會產生互動的設施。

### 步驟 3：列支援需求
後台行為需要什麼支撐？列為支援需求。本週只列選項（A/B/C），不做定案。用穩定代碼 SD-01 到 SD-NN。

### 步驟 4：畫可見線和內部互動線
可見線：前台和後台之間——線以上是顧客看得到的，以下是通常看不到的。
內部互動線：後台和支援之間——線以上是直接支持前台的，以下是間接的。

### 步驟 5：連結痛點到下游
CJM 的痛點 → 需要的後台行為 → 需要的支援系統 → 下游影響（功能或風格）。

### 最高指導原則
用業務用語描述，不用工程用語。後台用「角色+動作」，不用「系統功能」。支援需求列「需要什麼」，不列「用什麼技術」。
