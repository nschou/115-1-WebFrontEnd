# 04 服務藍圖範本（第 4 週）

> 學生根據本範本產生兩個檔案：
> - `04_blueprint.md` — 結論（藍圖表格 + 角色表 + 交接 + 決策選項版 + 可見線，固定格式）
> - `04_blueprint_rd.md` — 研究推導過程（服務流程分析 + 角色推導 + 選項比較論述）

---

## 04_blueprint.md 需包含的章節

### 1. 角色表

| 角色 | 工作事項 | 責任邊界 | 交接對象 | 由誰/什麼擔任 |
|---|---|---|---|---|
| [角色1] | [工作] | [不負責什麼] | [交接給誰] | [Persona/設施] |
| ... | ... | ... | ... | ... |

包含設施角色（如取餐櫃、店內看板）——它們是會產生互動的設施，當成角色不是系統功能。

### 2. 角色間交接說明

| 交接 | 從誰 | 到誰 | 交接內容 | 交接方式 |
|---|---|---|---|---|
| [交接1] | [從] | [到] | [內容] | [方式] |
| ... | ... | ... | ... | ... |

### 3. 服務藍圖表格

| 階段 | 前台（顧客經歷） | 後台（誰做什麼） | 支援需求（尚未定案） |
|---|---|---|---|
| [階段1] | [顧客做什麼] | [角色+動作] | [需求描述] |
| ... | ... | ... | ... |

前台用顧客經歷描述，後台用「角色+動作」，支援需求列選項（本週尚未定案）。

### 4. 例外情況

| 例外 | 觸發條件 | 處理方式 | 負責角色 |
|---|---|---|---|
| [例外1] | [條件] | [處理] | [角色鏈] |
| ... | ... | ... | ... |

### 5. 可見線與內部互動線

```
┌──────────────────────────────────────────┐
│ 前台行為（顧客面——顧客看得到的）              │
│   [前台行為列表]                            │
├──────── 可見線 ──────────────────────┤
│ 後台行為（店員面——通常顧客看不到的）           │
│   [後台行為列表]                            │
├──────── 內部互動線 ───────────────────┤
│ 支援需求（支援面——底層支撐）                  │

```

### 6. 服務方案選項分析（選項版，尚未定案）

| # | 服務需求 | 選項 | 分析 | 建議方向 |
|---|---|---|---|---|
| SD-01 | [需求] | A... B... C... | [優缺點分析] | [建議] |
| SD-02 | ... | ... | ... | ... |
| ... | ... | ... | ... | ... |

使用穩定決策代碼 SD-01 到 SD-NN。「採用方案」欄留空——第 5 週定案。

注意：此為選項版，不是定案版。「建議方向」是服務設計師的建議，不是老闆的決定。

## 04_blueprint_rd.md 需包含的內容

### A. 從 CJM 到 Blueprint 的推導

```
CJM 前台行為（03_cjm.md）
→ 對應每個階段的後台需要做什麼
→ 誰來做（角色）
→ 用什麼方式（支援需求）
```

### B. 角色推導論述

每個角色的推導過程：
- 從 Persona（02_persona.md）推導角色
- 角色的工作事項從哪來（Blueprint 後台行為推導）
- 責任邊界如何劃分
- 設施角色為什麼要納入（互動設施）

### C. 交接分析

每個交接點的分析：
- 為什麼需要這個交接
- 交接內容是什麼
- 交接方式如何決定
- 交接失敗會發生什麼

### D. 選項分析論述

每個服務需求的選項分析過程：
- 為什麼列出這些選項
- 每個選項的優缺點比較
- 建議方向的理由
- 為什麼不是定案（第5週才定案）

### E. 最高指導原則檢查

確認藍圖用業務用語描述，不用工程用語：
- 檢查每個後台行為是否用「角色+動作」描述
- 檢查支援需求是否用業務需求描述（不是系統功能）
- 如果有工程用語，記錄並改為業務用語

```
根據CJM前台行為和Persona角色，推導服務藍圖。
產生兩個檔案：
- 04_blueprint.md（角色表+藍圖表格+選項版+可見線）

決策表用穩定代碼SD-01~SD-NN，「採用方案」留空。
用業務用語，不用工程用語。如果資料不完整，提出問題。
```
