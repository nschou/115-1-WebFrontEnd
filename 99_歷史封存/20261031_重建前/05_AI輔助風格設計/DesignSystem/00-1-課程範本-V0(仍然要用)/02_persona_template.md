# 02 Persona 範本（第 2 週）

> 學生根據本範本產生兩個檔案：
> - `02_persona.md` — 結論（三層 Persona + 角色決定，固定格式）
> - `02_persona_rd.md` — 研究推導過程（Persona 推導論述，含來源）

---

## 02_persona.md 需包含的章節

### 1. 三層 Persona

#### 第一層：買單的決策者（主要 Persona）

| 欄位 | 填什麼 | 資料性質 |
|---|---|---|
| 姓名 | Persona 姓名 | 案例假設 |
| 基本資料 | 年齡、經驗、資金、規模 | 案例假設 |
| 使用情境 | 日常工作流程和時間分配 | 案例假設 |
| 目標 | 商業目標（3-5個） | 案例假設 |
| 痛點 | 現有痛點（3-5個） | 案例假設/研究依據 |
| 期望感受 | 情緒需求 | 設計推導 |
| 不期望感受 | 要避免的情緒 | 設計推導 |
| 擔任角色 | 在服務中擔任什麼 | 使用者指定 |

#### 第二層：主要服務使用者

同上欄位結構。來源標注同上。

#### 第三層：支持系統

同上欄位結構。來源標注同上。

## 02_persona_rd.md 需包含的內容

### A. Persona 推導過程

從市場選擇推導 Persona 的邏輯：

```
選定「[市場]」（01_market.md）
→ 目標客群是 [描述]
→ 買單的決策者需要 [特質] → Persona [姓名]
→ 主要使用者是 [特質] → Persona [姓名]
→ 支持系統需要 [特質] → Persona [姓名]
```

### B. 每個 Persona 的推導依據

每個 Persona 的每個欄位，記錄推導來源：
- 年齡/經驗 → 來自 [市場特徵/案例假設]
- 目標 → 來自 [市場分析/老闆目標]
- 痛點 → 來自 [行業研究/案例假設]
- 期望感受 → 來自 [從目標和痛點推導]

### C. 角色決定的推導

如有角色決定（如廚師），記錄：
- 為什麼需要這個決定
- 選項比較過程
- 選定理由
- 代價分析

### D. 資料性質標注

Persona 的資料通常多為 `案例假設`（教學設定）或 `設計推導`（從市場和行業推導）。少數痛點可能來自 `研究依據`。明確標注每一項。

## 使用方式

### 用 omp

```
請讀取 @02_persona_template.md 和 @01_market.md。
根據01_market.md的市場選擇和目標客群，推導三層Persona。
產生兩個檔案：
- 02_persona.md（三層Persona + 角色決定）
- 02_persona_rd.md（推導過程 + 來源標注）
每項資料標注資料性質。如果資料不完整，提出問題。
```
