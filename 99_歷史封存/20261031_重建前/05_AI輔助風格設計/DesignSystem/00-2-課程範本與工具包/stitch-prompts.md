# Google Stitch 操作指南：從服務設計到 DESIGN.md

> 本指南提供三段式 Prompt，搭配 Google Stitch 生成早餐店訂餐系統的 UI 設計與 DESIGN.md。
> 使用前請先登入 [stitch.withgoogle.com](https://stitch.withgoogle.com)（Google 帳號，完全免費）。
> 額度：每日 400 design credits + 15 redesign credits（UTC 午夜重置）。

---

## 階段一：探索——生成三組風格預設候選

**目標**：用相同的內容和資訊結構，生成三個不同風格方向的候選樣張，供比較選定。

**操作**：在 Stitch 首頁的文字輸入框貼入以下 Prompt：

---

```
為「雲端早餐店」設計顧客端訂餐系統。全部介面文案使用繁體中文。

【品牌背景】
這是一家「新型數位複合式連鎖」早餐店。老闆王建興（42歲，15年餐飲經驗）投資200萬創業，目標是數位點餐占比50%以上，未來展店。品牌人格：俐落、現代、可信賴。

【主要使用者】
張家豪，28歲軟體工程師，每天通勤路上用手機點早餐。期望：高效科技感、清楚、安心。不期望：油膩感、混亂感、焦慮感。

【服務流程（5個階段）】
1. 決定：通勤路上查看菜單，決定要吃什麼
2. 下單：選取品項，選取取餐時間，線上結帳
3. 等待取餐：到店附近，查看訂單進度（這是顧客最焦慮的階段——不知道要等多久）
4. 取餐：收到取餐通知，到取餐櫃領餐（取餐櫃會顯示取餐號碼）
5. 用餐：帶走或內用

【需要生成的畫面】
1. 顧客端首頁：今日推薦、菜單分群（主餐/套餐/飲品/加購）、下單按鈕
2. 下單確認頁：選取的品項清單、取餐時間選擇器、線上付款按鈕
3. 等待進度頁：訂單狀態（製作中→完成）、預計取餐時間、取餐號碼
4. 取餐通知頁：取餐號碼大字顯示、取餐櫃位置指引

【關鍵服務規則】
- 廚師在KDS上標記「完成」後，店員需確認餐點備妥、放入取餐櫃，才通知顧客——「廚師完成」和「店員確認可領取」是兩個不同步驟
- 取餐櫃是一個會產生互動的設施：它會通知顧客取餐號碼

【風格要求】
請生成 3 個不同風格版本，內容和佈局結構相同，只換風格參數：

A. 科技俐落：冷色基底（深青/灰藍）、無襯線幾何字體、緊湊間距、小圓角(4-8px)、快動效
B. 溫暖信賴：暖色但克制（米色/陶土）、無襯線圓潤字體、寬鬆間距、大圓角(12-16px)、慢動效
C. 平衡現代：冷暖混搭——冷色基底（深青）+ 暖色點綴（暖橙用於推薦標記和今日特餐）、無襯線中性字體、中等間距、中圓角(8-12px)、中速動效

【負面約束】
不要紫藍漸層背景、不要過度 SaaS 感、不要抽象幾何裝飾、不要 emoji 當圖示、不要全部圓角 16px、不要 Inter 字體加漸層標題。

【裝置】
手機優先設計（通勤路上使用）。
```

---

**產出**：Stitch 會生成多個畫面的設計，涵蓋三組風格方向。在畫布上比較三組結果。

## 階段二：收斂——選定方向並延伸

**目標**：從三組候選中選定一組，記錄選定理由和捨棄理由，延伸其他頁面。

**操作**：選定一組後（本案例建議選「平衡現代」C），在 Stitch 中繼續編輯：

---

```
我選定「平衡現代」方向。請在此風格基礎上：

1. 延伸以下畫面：
   - 付款頁：線上支付（信用卡/行動支付），配色要比其他頁面更穩重（傳達信任感）
   - 訂單完成確認頁：取餐號碼、預計取餐時間、取餐地點
   - 錯誤狀態頁：品項缺貨時的友善提示（柔和紅色，不是大紅警告）

2. 調整要求：
   - 確保「今日推薦」區塊用暖橙色點綴（推薦標記、特餐標籤）
   - 等待進度頁的留白要比其他頁面多（降低焦慮感）
   - 所有按鈕有明確的主次層次：主按鈕高對比色，次按鈕低調
   - 菜單品項分群清楚：主餐/套餐/飲品/加購四個區塊，區塊間留白

3. 保持一致：
   - 所有頁面同一套色彩、字體、圓角
   - 所有按鈕樣式一致（主按鈕/次按鈕/危險按鈕）
   - 所有卡片樣式一致
```

---

**選定理由記錄**（寫入講義中）：
- 選「平衡現代」：老闆品牌人格需科技感（→冷色基底），CJM最低點需安心感（→留白多、配色穩重），「複合式」需食物食慾感（→暖色點綴推薦區）
- 捨棄「科技俐落」：可能過冷，缺少食物食慾感和人情味
- 捨棄「溫暖信賴」：可能不夠俐落，不符合老闆「現代」目標和張家豪「科技感」期望

**注意**：以上是教學示範決策，未經老闆實際核准或使用者測試驗證。實務上應生成三組樣張後由老闆與設計師共同比較決定。

## 階段三：整理規格——匯出 DESIGN.md

**目標**：從選定的設計中匯出 DESIGN.md 規格檔案。

**操作**：

1. 在 Stitch 畫布上，**選取所有畫面**（必須全選才會出現匯出選項）
2. 點擊上方工具列的 **More**（更多）
3. 選擇 **Export**（匯出）
4. 選擇 **DESIGN.md**
5. 下載檔案

Stitch 會自動分析所有畫面的色彩、字體、間距、元件模式，生成符合 [Google Labs DESIGN.md 規格](https://github.com/google-labs-code/design.md)的檔案。

**匯出後檢查**：

1. 檔案是否包含 YAML frontmatter（`---` 開頭的 tokens 區塊）？
2. 是否包含所有 8 個標準章節（Overview / Colors / Typography / Layout / Elevation / Shapes / Components / Do's and Don'ts）？
3. 色彩是否有語義角色（primary / surface / accent / error）？
4. 是否包含互動狀態（hover / focus / disabled）？
5. 是否有繁體中文的設計理由說明？

如果 Stitch 生成的 DESIGN.md 缺少某些章節（如互動狀態或回溯表），可在 Claude Artifacts 中補充：

---

```
以下是我的 DESIGN.md 檔案內容：

[貼入從 Stitch 匯出的 DESIGN.md]

請補充以下缺失的內容，輸出完整的 DESIGN.md：

1. 每個元件的互動狀態（normal / hover / active / focus / disabled）
2. 表單元件規範（輸入框、標籤、錯誤狀態）
3. 回溯表：列出每個設計決策的依據和回溯來源
4. 標注哪些是設計假設（待驗證）

保持原有的色彩、字體、間距值不變。只補充缺失的部分。
```

---

## 完整流程總覽

```
階段一：Stitch 生成三組候選樣張
  ↓ 在畫布上比較
階段二：選定「平衡現代」，延伸其他頁面
  ↓ 記錄選定理由和捨棄理由
階段三：匯出 DESIGN.md
  ↓ 檢查格式完整性
（如有缺漏）Claude Artifacts 補充互動狀態和回溯表
  ↓
DESIGN.md 定稿 → 放入專案根目錄
```
