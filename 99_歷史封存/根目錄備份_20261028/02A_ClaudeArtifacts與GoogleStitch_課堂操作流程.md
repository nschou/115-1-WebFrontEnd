# 02A Claude Artifacts 與 Google Stitch 課堂操作流程

> 這是 02 講義「網站風格設計 × AI 工具（雙工具版）」的實作附件。
> 本週目標不是學會完整 HTML/CSS/JS，而是：從服務設計推導風格 → 用 Google Stitch 產生多個風格版本 → 用 Claude Artifacts 產生可執行網頁原型 → 整理成 `DESIGN.md` 初版。
> 不會設計也沒關係。這堂課只要求你照步驟，把服務設計的結果交給 AI 產生幾個風格版本，再學會判斷哪個版本最適合你的服務。

## 一、課前準備

### 學生課前

| 項目 | 說明 |
|---|---|
| Google 帳號 | 確認能登入 Gmail，用於 Google Stitch |
| Claude.ai 帳號 | 至 `claude.ai` 以 email 註冊，確認能登入並看到對話介面 |
| 第 1–2 週成果 | 準備好 `requirements.md`、角色卡、顧客旅程圖（電子檔） |
| 截圖工具 | 確認電腦或手機能截圖（Windows: Win+Shift+S / Mac: Cmd+Shift+4） |
| 文字編輯器 | 記事本或 VS Code 都可以，用來存 `DESIGN.md` |

### 老師課前

- 開課前一天測試 `claude.ai` 與 `stitch.withgoogle.com` 是否可從校園網路連線。
- 確認兩個工具是否仍免費、是否需信用卡、是否需手機驗證（截至撰寫時通常不需要，但政策可能變動）。
- 準備一組示範 Prompt 與一組備援資料包（示範截圖、範例 `DESIGN.md`、範例 HTML）。
- 若工具介面按鈕名稱與本文件不同，以現場介面為準，找「Create / Generate / Redesign / Export / Download / Share」等相近功能。

## 二、小組分工

每組建議 4 人，各司其職，避免一個人卡工具、全組停住：

| 角色 | 任務 |
|---|---|
| 操作員 | 實際操作 Google Stitch 與 Claude Artifacts |
| Prompt 設計員 | 整理與輸入提示詞，把服務設計成果轉成 AI 聽得懂的描述 |
| 紀錄員 | 截圖、記錄每個版本差異、保存對話重點與 AI 建議 |
| 批判員 | 判斷哪個版本符合服務設計，標記 AI 建議中哪些要採用、哪些要拒絕 |

> 如果只有 2–3 人一組，操作員兼 Prompt 設計員，紀錄員兼批判員即可。

## 三、課堂時間配置

總共 180 分鐘（3 小時），分成七段：

| 時間 | 任務 | 工具 | 產出 |
|---|---|---|---|
| 0–15 分 | 回顧 01 服務設計成果，寫核心體驗目標句 | 紙筆或文件 | 一句話體驗目標 |
| 15–35 分 | 推導品牌人格與風格方向 | Claude Artifacts 或 ChatGPT | 3 組風格方向 |
| 35–75 分 | 產生多個風格版本 | Google Stitch | 3–5 張首頁風格截圖 |
| 75–110 分 | 生成可執行原型 | Claude Artifacts | 1 個 HTML 原型 |
| 110–135 分 | 觀察程式碼與修正 | Claude Artifacts | 找出 header、色碼、按鈕 |
| 135–160 分 | 整理 DESIGN.md | Claude Artifacts 或 ChatGPT | 設計系統初版 |
| 160–180 分 | 小組分享與繳交 | 無 | 截圖＋反思 |

## 四、操作流程 A：推導品牌人格（0–35 分鐘）

### Step 1：回顧服務設計成果（15 分鐘）

全組一起把第 1–2 週的資料攤開，回答四個問題：

1. 誰是主要使用者？
2. 哪個流程最關鍵？
3. 哪個痛點最急？
4. 哪個接觸點最值得強調？

然後寫出一句話：

> 我們的早餐店網站，要讓「___」在「___」中感受到「___、___、___」。

範例：

> 我們的早餐店網站，要讓趕著上課的大學生，在早上 7:30–8:20 點餐時，感受到快速、清楚、可信任。

### Step 2：用 AI 推導品牌人格（20 分鐘）

**操作員**打開 Claude Artifacts（`claude.ai`），開新對話，貼入以下 Prompt：

```
我們在設計一個雲端早餐店訂餐管理系統。以下是第 1–2 週服務設計的成果：

【在這裡貼上你的角色卡、旅程圖重點、主要痛點、核心功能】

我們的核心體驗目標是：【貼上上面寫的那句話】

請幫我們：
1. 推導 3 組適合的品牌人格，每組包含：品牌人格形容詞、色彩方向、字體方向、版面密度建議
2. 用表格呈現
3. 說明每組為什麼適合這個服務情境
4. 標示哪些設計語言不建議採用
```

**紀錄員**截圖保存 AI 回覆。**批判員**判斷：3 組方向中哪一組最符合你們的服務？

## 五、操作流程 B：Google Stitch 風格探索（35–75 分鐘）

### Step 1：登入 Google Stitch

1. 打開瀏覽器，進入 `stitch.withgoogle.com`
2. 使用 Google 帳號登入
3. 如果要求設定隱私選項，建議關閉「允許對話內容用於模型訓練」

> 如果連不上：見第九節「常見問題與備援」。

### Step 2：新增專案並輸入 Prompt

1. 點「Create」或「New」新增一個新專案
2. 在輸入區貼入以下 Prompt（Prompt 設計員負責填入你們的資料）：

```
為「雲端早餐店訂餐管理系統」設計顧客端首頁。

品牌人格：【貼上你們選定的品牌人格，例如：溫暖、有效率、可信任】
主要使用者：【貼上主要使用者與情境，例如：趕著上課的大學生，早上 7:30–8:20 尖峰點餐】
色彩方向：【貼上色彩方向，例如：暖米色背景、蛋黃色主色、深咖啡文字】
字體：【貼上字體方向，例如：無襯線、清楚易讀】
版面：【貼上密度方向，例如：緊湊但不擁擠，卡片分區清楚】

請生成顧客端首頁，包含：
- Hero 區：今日套餐標題＋立即下單按鈕
- 下方：熱門品項卡片列表（3–4 個品項）
- 頁首：品牌名稱＋購物車圖示

不要使用：紫藍漸層、過度 SaaS 感、抽象科技背景、三欄制式卡片、太像後台 ERP。
要像：有溫度但有效率的早餐服務。
```

### Step 3：生成第一版並截圖

1. 點「Generate」或類似按鈕
2. 等待生成完成
3. **紀錄員**截圖，檔名存為 `stitch_v1_快速清楚.png`
4. 在截圖旁標註：這一版的優點是什麼？缺點是什麼？

### Step 4：生成第二版（換方向）

修改 Prompt 中的品牌人格或色彩方向，重新生成。例如：

```
（把上面的 Prompt 貼上，但修改以下部分）
品牌人格：鄰家、親切、有人情味
色彩方向：暖色系、米色、黃色、橘色
版面：舒適、留白中等
```

截圖存為 `stitch_v2_人情味.png`。

### Step 5：生成第三版（AI 建議方向）

```
（把上面的 Prompt 貼上，但加入這句）
請由你建議一個最適合這個服務的第三方向，並說明理由。
```

截圖存為 `stitch_v3_AI建議.png`。

### Step 6：小組比較

全組一起看 3–5 張截圖，**批判員**帶領討論：

- 哪一版最像「這個服務」？
- 哪一版只是好看，但不適合早餐店真實情境？
- 哪一版最適合後續做成真正前端？
- AI 有沒有跑出「紫藍漸層」「SaaS 感」？如果有，是 Prompt 不夠明確還是 AI 自己跑偏？

> 選定 1–2 個最符合的方向，等一下交給 Claude Artifacts 做收斂。

## 六、操作流程 C：Claude Artifacts 生成原型（75–135 分鐘）

### Step 1：開新對話

1. 打開 `claude.ai`
2. 點「New chat」開新對話

### Step 2：貼入生成原型 Prompt

**操作員**貼入以下 Prompt（填入你們選定的風格方向）：

```
請用 HTML + CSS + JavaScript 生成一個「雲端早餐店訂餐系統」顧客端首頁原型。

品牌風格：【貼上你們從 Google Stitch 選定的風格描述】
色彩：暖米色背景 #fbf6ec、蛋黃色主色 #f2b705、深咖啡文字 #3d2e1f、暖橘強調 #e8743c
字體：無襯線，標題較粗，內文清楚易讀
版面：手機優先 RWD，卡片分區，留白適中

內容：
- 頁首：品牌名稱「晨光早餐」＋購物車圖示（數字 2）
- Hero 區：「今日套餐」標題＋副標「全麥三明治＋拿鐵」＋「立即下單 $90」按鈕
- 下方：熱門品項卡片列表（全麥三明治 $45、蛋餅 $35、拿鐵 $55），每張卡片有品名、簡述、價格、加購「＋」按鈕
- 頁尾：簡單版權文字

請用單一 HTML 檔，內嵌 CSS 與 JS。
不要使用紫藍漸層、不要過度 SaaS 感、不要抽象背景。
要像：有溫度但有效率的早餐服務。
```

### Step 3：等待 Artifact 出現並預覽

1. Claude 會生成一個 Artifact（互動網頁）
2. 在對話中應該會看到預覽畫面
3. 如果沒有自動出現，試著在回覆中找「View」或預覽按鈕

### Step 4：用對話迭代修改

看到第一版後，用自然語言要求修改。**操作員**一次只改 1–3 點，不要一次改太多：

```
這個版本需要調整：
1. 按鈕太小，請放大並加圓角
2. 卡片之間太擠，請加大間距
3. 色彩太冷，請把背景改成更暖的米色

請保留其他部分不動，只調整上述幾點。
```

**紀錄員**每次修改後截圖，記錄改了什麼。

### Step 5：觀察程式碼（不要求完全看懂）

這一步很重要，但不要害怕。你只需要做三件事：

#### 觀察任務一：找出頁首

在程式碼中搜尋 `<header` 或 `<nav`，看看頁首的 HTML 長什麼樣。

> 你會看到類似 `<header>...<div>晨光早餐</div>...</header>` 的結構。
> 這就是畫面頂部的品牌名稱與購物車區塊。

#### 觀察任務二：找出色彩設定

在程式碼中搜尋 `#f`（CSS 色碼開頭），看看有沒有出現你指定的顏色。

> 你應該能找到 `#fbf6ec`（米色背景）、`#f2b705`（蛋黃主色）、`#3d2e1f`（深咖啡文字）。
> 這些色碼就是 AI 把你的風格規格變成程式碼的證據。

#### 觀察任務三：找出按鈕

在程式碼中搜尋「立即下單」，看看按鈕的 HTML 長什麼樣。

> 你會看到類似 `<button>立即下單 $90</button>` 的結構。
> 這就是畫面上那顆黃色按鈕的程式碼。

> 本週只要求「看出大概結構」，不要求理解完整 CSS 或 JS。看不懂的部分標記起來就好，那是第 4–6 週要學的。

### Step 6：截圖與保存

1. **紀錄員**截圖最終版本的原型畫面，存為 `artifacts_final.png`
2. 如果可以，複製程式碼存成 `breakfast_prototype.html`，作為第 4–6 週參考
3. 不要直接把這份程式碼當作業提交，要理解後再修改

## 七、操作流程 D：整理 DESIGN.md（135–160 分鐘）

### Step 1：用 AI 生成設計系統文件

**操作員**在 Claude Artifacts 同一對話中（或開新對話），貼入：

```
請根據我們剛才設計的早餐店網站，輸出一份 DESIGN.md（Markdown 格式）。

我們的服務定位：【貼上服務設計摘要】
我們的品牌人格：【貼上選定的品牌人格】
我們選定的風格方向：【貼上風格描述】

DESIGN.md 需包含：
1. 風格一句話定義
2. 主要使用者與情境
3. 核心體驗目標
4. 品牌人格
5. 色彩規則（主色、輔色、背景、文字、狀態色，附 hex 色碼）
6. 字體規格（標題、內文、按鈕、標籤的大小與粗細）
7. 間距與密度（4px 系統）
8. 按鈕、卡片、表單規格
9. 互動狀態規則（hover、focus、active、loading）
10. 不要出現的風格特徵

請說明每個決策如何對應我們的服務體驗目標。
```

### Step 2：人工審查與修正

**批判員**帶領全組檢查 AI 輸出的 DESIGN.md：

- 色彩是否符合我們選定的方向？（不是 AI 自己編的）
- 字體大小是否合理？（不要全部太大或太小）
- 元件規則是否合理？（按鈕不會過度裝飾）
- 「不要出現的風格特徵」是否列清楚？

修正後存成 `DESIGN.md`。

## 九、常見問題與備援

### 無法登入 Claude.ai

- 確認 email 已驗證。
- 換瀏覽器試試（建議 Chrome）。
- 如果仍無法使用：本組可只用 Google Stitch 完成風格探索，並使用老師提供的範例 HTML 做程式碼觀察。

### Google Stitch 連不上

- 確認 Google 帳號已登入。
- 換瀏覽器試試。
- 如果學校網路擋了：用手機熱點測試，或使用老師提供的示範截圖完成風格分析。

### 額度用完

- Claude Artifacts：免費版有每日訊息量限制。如果用完，改用 ChatGPT 免費版做文字推理（品牌人格推導、DESIGN.md 生成）。
- Google Stitch：如果生成額度用完，用已生成的版本做比較即可，不需要再生成新的。

### 手機驗證卡住

- 部分帳號註冊時可能要求手機驗證。如果卡住，換一個 email 試試，或請同學幫忙用已驗證的帳號操作。

### 學生不想建立 AI 帳號

- 可以。以小組為單位共用操作，由一位同學操作、其他同學記錄與批判。
- 或使用老師提供的示範截圖與範例程式碼完成分析。
- 核心評量目標是「能否從服務設計推導出合理風格規格」，而非是否用了特定工具。

### AI 生成結果太醜

- 檢查 Prompt 是否太短或太抽象。加入更多具體描述：色彩 hex 色碼、字體方向、版面密度。
- 加入「負面約束」：不要紫藍漸層、不要 SaaS 感、不要抽象背景。
- 用對話要求修改：「這太醜了，請改成更溫暖、更整齊的風格」。

### AI 生成結果太像 SaaS

- 在 Prompt 中加入：「不要像企業 SaaS、不要像後台 ERP、要像早餐店」。
- 加入參考描述：「要像有溫度但有效率的早餐服務，不是科技公司的 Dashboard」。

### AI 產生的程式碼看不懂

- 這很正常。本週只要求找出三件事：`<header>`、色碼、按鈕文字。
- 看不懂的部分標記起來，那是第 4–6 週要學的。
- 不要因為看不懂就焦慮，本週的目標是「看到風格如何變成程式碼的樣子」，不是學會寫程式碼。

### 兩個工具都用不了

- 使用老師提供的備援資料包：示範截圖、範例 `DESIGN.md`、範例 HTML。
- 以紙筆完成風格問卷與轉譯表，用範例截圖做風格比較分析。
- 仍可完成作業一（轉譯表＋反思），作業二用範例資料做分析。

## 十、倫理與資料安全

- 不上傳真實姓名、電話、地址、訂單資料。
- 不上傳真實店家的 Logo、菜單、照片。
- 課堂一律使用假資料與示範品牌（如「晨光早餐」）。
- 參考其他網站風格時，只分析設計語言，不直接抄襲版面與品牌識別。
- AI 生成結果必須由學生人工判斷與修正，不能直接當作業提交。

## 附錄 B：第 4 週起 VS Code AI 擴充套件安裝指南

本週（第 3 週）使用 Claude Artifacts 與 Google Stitch 做風格探索。從第 4 週開始，學生需要在 VS Code 中安裝 AI 擴充套件，協助 HTML/CSS/JS 與 React 的實作。以下安裝指南可提前發給學生，建議第 3 週下課後或第 4 週第一堂課花 15 分鐘帶全班一起安裝。

### 階段一：第 4–6 週使用 Codeium（即裝即用）

Codeium 是最簡單的入門方案，不需信用卡、不需學生驗證，安裝完就能用。

#### 安裝步驟

1. 打開 VS Code
2. 點左側「Extensions」圖示（或按 Ctrl+Shift+X）
3. 搜尋「Codeium」
4. 點「Install」安裝
5. 安裝後側邊欄會出現 Codeium 圖示，點它
6. 按「Sign in」用 Google 或 GitHub 帳號登入
7. 登入完成後，回到編輯器即可使用

#### 功能說明

- **自動補全**：打字時會灰色顯示建議，按 Tab 接受
- **AI 對話**：側邊欄 Codeium 面板可問問題，每日 10 則
- **用途**：第 4–6 週寫 HTML/CSS/JS 時，用自動補全加速，用對話問語法

> 每日 10 則對話對課堂練習夠用。如果用完，可以等隔天重置，或改用 Claude/ChatGPT 免費版問語法問題。

### 階段二：第 7–10 週引入 Google Antigravity（代理式編碼）

框架階段需要更強的 AI 代理能力，建議引入 Google Antigravity。它完全免費，只需 Google 帳號。

#### 安裝步驟

1. 到 `antigravity.google` 下載桌面版 IDE，或使用 CLI 安裝
2. 以 Google 帳號登入
3. 若要在 VS Code 中使用，可安裝 Antigravity 的 VS Code 擴充套件（如有提供）
4. 開啟專案後，用自然語言描述要做什麼，Antigravity 會代理執行

#### 功能說明

- **代理式編碼**：描述需求，AI 自動導航程式碼、多檔編輯、執行指令
- **模型**：Gemini（Google 最新模型）
- **用途**：第 7–10 週 React 實作，用代理生成元件骨架、重構、串接 API
- **費用**：完全免費

> Google Antigravity 於 2026 年 9 月正式上線，非常新。老師開課前需先自行測試台灣連線穩定性與功能完整度。若不穩定，改用下方 GitHub Copilot 備援方案。

### 備援：GitHub Copilot 學生免費版

如果 Google Antigravity 不可用或不穩定，可使用 GitHub Copilot 學生版作為備援。

#### 申請步驟

1. 確認已有 GitHub 帳號（如果沒有，先至 `github.com` 註冊）
2. 到 `github.com/settings/education/benefits`
3. 點「Start an application」開始學生驗證
4. 填寫學校資訊並上傳學生證或在學證明
5. 等待驗證（通常 1–2 天，建議第 3 週就先申請）
6. 驗證通過後，到 `github.com/github-copilot/free_signup` 啟用 Copilot
7. 在 VS Code 安裝「GitHub Copilot」擴充套件
8. 安裝後用 GitHub 帳號登入即可

#### 功能說明

- **自動補全**：無限次數
- **AI 對話**：每月 200 次 AI Credits 額度
- **模型**：自動選擇（免費版不能自選模型）
- **用途**：第 7–10 週 React 實作，自動補全元件骨架，對話問框架問題

> 注意：2026 年 6 月回歸的學生版額度已縮減，從「等同 Pro」降為 200 次 AI Credits/月。自動補全仍無限，但對話與代理功能有限。建議作為 Antigravity 的備援，而非主線。

### 驗證還沒通過時的替代方案

如果到第 7 週學生驗證還沒通過，可使用以下替代：

- **Google Antigravity**：完全免費，只需 Google 帳號，推薦優先使用
- **GitHub Copilot Free**（非學生版）：任何有 GitHub 帳號者可用，每月 2,000 次補全＋50 次對話
- **繼續使用 Codeium**：雖然每日對話只有 10 則，但無限自動補全仍可使用
- **Gemini Code Assist**：VS Code 搜尋安裝，Google 出品，免費版額度較大

### 課堂安裝帶領建議

老師可在第 4 週第一堂課的前 15 分鐘，帶全班一起安裝 Codeium：

1. 全班打開 VS Code
2. 一起搜尋並安裝 Codeium
3. 一起登入
4. 老師示範：打一個 `<div>` 看 Codeium 自動補全
5. 老師示範：在側邊欄問「Flexbox 怎麼置中？」
6. 確認每個人都裝好、能用
7. 同時鼓勵有 GitHub 帳號的學生課後申請 Copilot 學生版
