# 02 網站風格設計 × AI 工具：課程講義（Claude Artifacts＋Google Stitch 雙工具版）

## 模組定位

本模組聚焦在「如何把抽象的網站風格，轉化成可被設計、可被溝通、可被前端實作、可被 AI 工具穩定使用的設計系統」。近年的 AI 設計工具已能以自然語言生成原型、Landing Page 與設計稿，但若缺乏清楚的品牌與風格規格，結果常流於同質化、模板化與典型的「AI 味」視覺。另一方面，越來越多工作流開始把風格規則整理成 AI 可讀的設計文件，讓 AI 在生成 UI 與前端程式時有明確依循，而不是每次重新猜測。

本模組適合放在整體課程的第 3 週，位於服務設計（第 1–2 週）與前端基礎（第 4–6 週）之間。學生先完成早餐店訂餐系統的服務概念、角色流程、顧客旅程與需求文件，再透過本模組建立品牌風格、視覺語言與設計系統，作為後續前端框架實作的共同依據。

## 先備連結：02 為什麼取決於 01

本講義最重要的前提是：**網站風格不是從「我喜歡什麼」開始，而是從第 1–2 週的服務設計成果開始。** 服務設計研究與品牌體驗研究都指出，品牌體驗不是靠單一視覺元素孤立形成，而是透過服務接觸點、主題體驗、顧客導向安排與一致的刺激共同累積而成。

因此，第 3 週不是憑空討論「文青風、科技風、可愛風」，而是要回答這些問題：

- 這個早餐店系統主要服務誰？
- 他們在什麼情境下使用？
- 在旅程中最在意什麼？速度、安心、親切、清楚，還是品牌感？
- 哪些接觸點最關鍵？
- 我們希望顧客在每個接觸點感受到什麼？

換句話說，**01 講義決定「服務是什麼」，02 講義決定「這個服務看起來與感覺起來像什麼」**。如果沒有這個轉譯步驟，網站風格很容易淪為主觀審美，而不是服務與品牌策略的一部分。

## 學習目標

學生完成模組後，應該能：

1. 把「喜歡、溫暖、科技感」這種抽象形容詞拆成可操作的視覺與互動元素（色彩、字體、密度、元件語言等）。
2. 從第 1–2 週的服務設計成果，推導出合理的網站風格方向，而不是只憑個人喜好選風格。
3. 使用 Claude Artifacts 與 Google Stitch 兩個免費 AI 工具，建立多個風格方向，並進行比較與收斂。
4. 把選定風格整理成一份設計系統／`DESIGN.md`：色彩、字體、間距、元件規則，供後續前端開發使用。
5. 避免「AI 味」的視覺，用 AI 做高品質草稿，再透過人類品味做最後的整合。
6. 觀察 Claude Artifacts 生成的 HTML/CSS/JS 程式碼，建立「風格規格→程式碼」的對應意識，為第 4–6 週前端落地做準備。

## 核心觀念：從服務設計走到網站風格

### 為什麼不能直接選喜歡的風格

許多初學者在做網站時，會先說「我想做簡約風」或「我喜歡科技感」，但這種做法忽略了服務設計的本質：設計應該回應使用者目標與使用情境。品牌視覺若脫離定位、識別、信任與轉化邏輯，就可能只有好看，卻無法支持真正的服務體驗與商業目標。

以早餐店為例，如果你的顧客大多是趕上課與上班的人，他們在旅程裡最重視的通常是快、清楚、可預期；那麼網站風格就不適合做成過度藝術化、資訊太散、操作太慢的畫面。相反地，如果服務主打「假日早午餐、拍照分享、風格品牌」，網站就可以容許更多故事感與視覺表現。

### 服務設計如何影響品牌體驗

研究指出，使用者導向的服務設計、主題體驗規劃與接觸訓練，會正向影響品牌體驗與滿意度。這表示網站風格不只是視覺裝飾，而是品牌體驗的一部分：它要把服務設計中承諾的感受，穩定地表現在每個數位接觸點上。

### 服務設計到網站風格的轉譯公式

老師可直接教學生用下面這條公式：

**服務設計成果 → 關鍵使用情境 → 使用者核心感受 → 品牌人格 → 視覺語言 → 網站風格規格**

也就是說，網站風格不是從配色開始，而是從「這個服務想讓誰在什麼情境下得到什麼感受」開始。

## 風格轉譯步驟（本講義核心）

以下六步，是本模組最重要的教學主軸，老師可直接照這個順序上課。每一步都標明使用哪個工具。

### Step 1：回看 01 的服務設計成果

**使用工具**：紙筆或文件討論，不需 AI

先要求學生把第 1–2 週做好的資料攤開：

- 角色卡（顧客、店員、老闆）
- 顧客旅程圖
- 服務藍圖
- `requirements.md`

這一步的目的不是重做服務設計，而是找出「哪些資訊會直接影響風格」。顧客旅程圖與服務藍圖常被用來看見關鍵接觸點與體驗差異，因此它們不只影響流程，也能成為視覺與品牌體驗設計的依據。

老師要引導學生回答：

- 哪個角色是主要使用者？
- 哪個流程最關鍵？
- 哪個痛點最急？
- 哪個接觸點最值得被強調？

### Step 2：找出「核心體驗目標」

**使用工具**：Claude Artifacts 或 ChatGPT 免費版（文字推理）

從服務設計資料中，挑出這個系統最想讓使用者感受到的 2–3 個核心感受。例如：

- 快速
- 安心
- 清楚
- 親切
- 有品質
- 在地感

這一步非常重要，因為風格不是要反映全部，而是要優先放大最重要的體驗目標。品牌與體驗設計相關內容都強調，視覺應該服務於識別、信任與轉化，而不是無目的堆疊美感。

老師可以直接要求每組完成一句話：

> 我們的早餐店網站，要讓「___（主要使用者）」在「___（主要情境）」中感受到「___、___、___」。

例如：

> 我們的早餐店網站，要讓趕著上課的大學生，在早上 7:30–8:20 點餐時，感受到快速、清楚、可信任。

**Prompt 範例（Claude Artifacts）**：

```
我們在設計一個雲端早餐店訂餐管理系統。以下是第 1–2 週服務設計的成果：
【貼上角色卡、旅程圖重點、主要痛點】
請幫我們找出這個系統最該傳達的 2–3 個核心體驗目標，
並用一句話總結：「我們的早餐店網站，要讓___在___中感受到___」。
```

### Step 3：把核心體驗目標轉成品牌人格

**使用工具**：Claude Artifacts 或 ChatGPT 免費版

接著，把這些感受轉成品牌人格，而不是直接變成顏色。因為「快速」不是顏色，「安心」也不是字體，它們需要先被轉成品牌角色與口氣。

例如：

| 服務設計輸出 | 核心體驗目標 | 品牌人格 |
|---|---|---|
| 上班族尖峰時段快速點餐 | 快速、清楚、穩定 | 俐落、可靠、有效率 |
| 在地社區早餐熟客回訪 | 親切、熟悉、溫暖 | 鄰家、可信、有人情味 |
| 假日早午餐品牌經營 | 放鬆、質感、分享感 | 風格感、講究、生活感 |

這種從服務情境到品牌人格的推導，可以避免學生直接跳到「我想用粉色」這種沒有依據的決策。

**Prompt 範例（Claude Artifacts）**：

```
根據以下核心體驗目標（快速、清楚、可信任），
請推導 3 組適合的品牌人格與網站風格方向，
每組包含：品牌人格形容詞、適合的色彩方向、字體方向、版面密度建議。
請用表格呈現，並說明每組為什麼適合這個服務情境。
```

### Step 4：把品牌人格轉成視覺語言

**使用工具**：Claude Artifacts 或 ChatGPT 免費版

到了這一步，才開始進入設計語言。老師可要求學生把品牌人格拆成以下六個面向：

- 色彩策略
- 字體氣質
- 版面密度
- 元件語言
- 圖像語言
- 動態節奏

例如：

| 品牌人格 | 色彩 | 字體 | 版面 | 元件 | 圖像 |
|---|---|---|---|---|---|
| 俐落、可靠、有效率 | 低彩度暖色或中性底＋高辨識主色 | 無襯線、清楚易讀 | 緊湊但不擁擠 | 按鈕明確、卡片規則性高 | 清楚餐點圖、少裝飾 |
| 鄰家、親切、有人情味 | 暖色系、米色、黃色、橘色 | 柔和無襯線或人文感字體 | 舒適、留白中等 | 圓角中等、陰影輕 | 實拍與在地感素材 |
| 風格感、講究、生活感 | 低飽和質感色 | 精緻標題字＋易讀本文字 | 留白多、節奏慢 | 元件更克制 | 生活感照片或編排感更強 |

這就是從服務設計轉譯到視覺系統的關鍵步驟。

### Step 5：產生多個風格版本並比較

**使用工具**：Google Stitch（大量探索）＋ Claude Artifacts（收斂與程式碼觀察）

這一步是雙工具策略的核心。同一個服務定位，先用 Google Stitch 快速生成多個風格版本，再用 Claude Artifacts 做收斂與程式碼觀察。

#### 5a. 用 Google Stitch 做大量風格探索

Google Stitch 的優勢是免費額度較大，適合「同題多版本」探索。老師可要求學生：

- 上傳第 1–2 週的服務設計文件或參考網站截圖
- 用文字描述品牌人格與服務情境
- 一次生成 3–5 個風格變體（可用同一份 Prompt 重複生成，或調整方向後再生成）

**Google Stitch 操作步驟**：

1. 進入 `stitch.withgoogle.com`，以 Google 帳號登入
2. 上傳參考資料（圖片、PDF 需求文件、或網站 URL）
3. 輸入結構化指令（見下方 Prompt 範例）
4. 生成後用 Redesign 功能微調（每日 15 次）

**Google Stitch Prompt 範例**：

```
為「雲端早餐店訂餐管理系統」設計顧客端首頁。
品牌人格：溫暖、有效率、可信任。
主要使用者：趕著上課的大學生。
使用情境：早上 7:30–8:20 尖峰快速點餐。
色彩方向：暖米色背景、蛋黃色主色、深咖啡文字。
字體：無襯線、清楚易讀。
版面：緊湊但不擁擠，卡片分區清楚。
請生成 3 個不同風格版本：
A 強調快速清楚、B 保留效率但更有人情味、C 由你建議第三方向。
不要使用紫藍漸層、不要過度 SaaS 感、不要抽象背景。
```

#### 5b. 用 Claude Artifacts 做收斂與程式碼觀察

從 Google Stitch 的多個版本中，選出最符合服務的 1–2 個方向，再用 Claude Artifacts 生成可執行的 HTML/CSS/JS 版本。

Claude Artifacts 的優勢是：生成的就是真實網頁程式碼，學生可以直接看到「風格如何變成程式」。

**Claude Artifacts 操作步驟**：

1. 進入 `claude.ai`，登入免費帳號
2. 在對話中描述要生成的頁面（見下方 Prompt 範例）
3. Claude 會生成一個 Artifact（互動網頁），可直接在介面中預覽
4. 用對話持續迭代修改（「把配色改成暖色」「加一個購物車區塊」）
5. 點擊「View Code」可看到生成的 HTML/CSS/JS 原始碼

**Claude Artifacts Prompt 範例**：

```
請用 HTML + CSS + JavaScript 生成一個「雲端早餐店訂餐系統」顧客端首頁原型。
要求：
- 品牌人格：溫暖、有效率、可信任
- 色彩：暖米色背景(#fbf6ec)、蛋黃色主色(#f2b705)、深咖啡文字(#3d2e1f)、暖橘強調(#e8743c)
- 字體：無襯線，標題較粗，內文清楚易讀
- 版面：手機優先 RWD，卡片分區，留白適中
- 內容：Hero 區放「今日套餐」＋「立即下單」按鈕，下方放熱門品項卡片列表
- 不要使用紫藍漸層、不要過度 SaaS 感
- 請用單一 HTML 檔，內嵌 CSS 與 JS
```

**迭代修改 Prompt 範例**：

```
這個版本太像企業 SaaS，請做以下調整：
1. 把按鈕圓角加大，更有親切感
2. Hero 區加一張早餐圖片的佔位區
3. 卡片之間留白加大，讓節奏慢一點
4. 整體色彩飽和度降低 10%，更耐看
```

#### 5c. 比較與選擇

然後請學生比較：

- 哪一版最像「這個服務」？
- 哪一版雖然好看，但不符合流程效率？
- 哪一版最適合後續做成真正前端？
- Claude Artifacts 生成的程式碼，哪些部分看得懂、哪些看不懂？

### Step 6：收斂成 `STYLE_GUIDE.md` / `DESIGN.md`

**使用工具**：Claude Artifacts 或 ChatGPT 免費版

最後，把選定風格整理成可被後續前端使用的規格文件：

- 風格一句話定義
- 主要使用者與情境
- 核心體驗目標
- 品牌人格
- 色彩規則（含 hex 色碼）
- 字體規則
- 間距與密度
- 按鈕、卡片、表單規格
- 不要出現的風格特徵

**Prompt 範例（Claude Artifacts）**：

```

輸出一份 DESIGN.md（Markdown 格式），需包含：

2. 字體規格（標題、內文、按鈕、標籤的大小與粗細）
3. spacing scale（4px 系統）

5. 互動狀態規則（hover、focus、active、loading）

```

這一步很重要，因為後續第 4–6 週做 HTML/CSS/JS 時，不是重新發明風格，而是把這份規格落地。

## UX 原則 × 風格決策：從體驗邏輯到視覺規則

在前面的章節，我們已經說明風格如何從 01 的服務設計推導出來。接下來要補上一段更「工程化」的教學：讓學生看到常見的 UX 原則，如何具體對應到風格決策與實作。這一節的目標，是幫學生建立「先問 UX 問題，再做風格決策」的習慣，而不是直接用喜好選長相。

> 本節的錯誤範例與正確範例，已製作成可互動的展示網站，課堂可直接投影切換比較：
> **https://ns-wfe115-1.pplx.app**

---

### 一、一致性原則 × 品牌風格與信任感

**1. UX 原則/方法的目的**

- 目的：讓使用者在不同頁面和情境下，都能感覺自己仍在同一個產品裡，不需要每次重新學習操作方式。
- 要解決的 UX 問題：降低認知負荷、建立預期、增加信任感（「這系統是可靠的」）。

**2. 對應的風格要做什麼**

- 把色彩、字體、按鈕樣式、卡片風格、圖像語言固定成一套規則（設計系統），跨頁面一致。
- 顧客端、店員端雖然功能與資訊密度不同，但在顏色、字體、元件形狀上保持一致，讓人一眼看出是同一品牌。

**錯誤範例（早餐店情境）**

- 顧客首頁：暖米色背景、圓角按鈕、實拍早餐照片。
- 菜單頁：忽然變成冷色藍綠、銳角按鈕、抽象插畫。
- 店員端：使用完全不同的字體與顏色，看起來像另一套系統。

結果：使用者與店員都會懷疑是否進入了不同系統，信任感下降，也難建立穩定預期。

**正確範例**

- 顧客首頁、菜單頁、購物車都使用同一套主色（米色＋蛋黃色）、同一種無襯線字體、同樣圓角大小的按鈕。
- 店員端改成資訊密度較高的排版，但仍採用同一色系與字體，只在布局與密度上作調整。

結果：顧客與店員都能感覺自己在同一個早餐品牌系統裡，學會一套操作後，其他頁面也容易上手。

---

### 二、視覺層次 × 哪裡先被注意到

**1. UX 原則/方法的目的**

- 目的：讓使用者一眼看出最重要的資訊與操作，不需要在畫面中四處尋找。
- 要解決的 UX 問題：減少搜尋成本、縮短完成目標時間、避免漏看關鍵訊息。

常見方法：字級、粗細、顏色對比、位置、留白、群組化等。

**2. 對應的風格要做什麼**

- 用字級、顏色、位置和留白，強化「主要 CTA」和「關鍵資訊」，讓它們自然成為視覺中心。
- 在早餐店首頁，把「今日套餐」、「立即下單」做成最醒目的區塊，而不是被品牌故事或次要文字淹沒。

**錯誤範例**

- 首頁上方用最大字級放長篇品牌故事，顏色最亮。
- 「立即下單」按鈕被放在右下角，小小一顆，顏色接近背景。
- 菜單卡片中，菜名、價格、描述文字字級都一樣，看不到重點。

結果：顧客進入首頁先看到大量故事，不知道可以直接點餐；主行動藏起來，流程被拖慢。

**正確範例**

- Hero 區左側：大標「今日套餐」、副標簡短說明，再配一張清楚餐點照片。
- Hero 區右側或下方：一顆高對比色的主按鈕「立即下單」。
- 菜單卡片：菜名與價格使用稍大的字級與粗體，描述文字略小且顏色偏灰，視覺上先讀到「是什麼」與「多少錢」。

結果：顧客一眼就知道要從哪裡開始操作，也知道菜單中哪些資訊是重點，不需要花力氣到處找。

---

### 三、Hick's Law × 版面密度與分群風格

**1. UX 原則/方法的目的**

- 目的：選項越多、越複雜，決策時間就越長；透過分群與分步減少一次決策負擔。
- 要解決的 UX 問題：避免「太多選擇而決策癱瘓」，尤其在菜單或設定頁面。

**2. 對應的風格要做什麼**

- 在需要快速決策的地方（例如早上尖峰點餐），版面風格要偏「清楚、分群、留白足夠」，而不是滿版文字與裝飾。
- 用卡片、區塊、標題分組，把菜單分成主食、套餐、飲品、加購等幾個視覺群組，讓使用者先選群，再選品項。

**錯誤範例**

- 菜單頁用一個長表格列出所有品項：早餐、午餐、飲料、甜點、加購全部在同一區。
- 字體大小幾乎一致，沒有分組標題，背景還有花俏圖案干擾閱讀。

結果：顧客要一行一行看，非常耗時間；在尖峰時段容易放棄或隨便選一項，不符合「快速點餐」的服務目標。

**正確範例**

- 菜單頁分成 3–4 個區塊，每個區塊有清楚標題（例如「主餐」、「套餐」、「飲品」、「加購」）。
- 每個區塊用卡片呈現，卡片內只顯示必要資訊（品名、簡述、價格、加購按鈕）。
- 區塊之間保留明顯留白，讓視覺自然分段，減少一次看到過多選項的壓力。

結果：顧客先在小範圍內做決定（例如先選「主餐」），再選具體品項，決策負擔降低，整體流程更流暢。

---

### 四、審美可用性效應 × 初次信任與情緒

**1. UX 原則/方法的目的**

- 目的：美觀的介面會被認為更好用，使用者更願意容忍小錯誤並持續探索。
- 要解決的 UX 問題：初次印象與信任建立，避免「系統看起來很爛」的負面偏見。

**2. 對應的風格要做什麼**

- 避免凌亂排版、未對齊元素、過度使用顏色與字體的視覺雜訊。
- 用穩定色系、合適字體、合理留白做出「有在用心、可靠」的品牌感，尤其在訂單確認與付款頁面。

**錯誤範例**

- 菜單卡片大小不一、對齊混亂，間距不固定。
- 同一頁面混用多種字體，部分使用系統預設字體、部分使用花體。
- 背景、按鈕、卡片各用不同強烈顏色，缺乏視覺秩序。

結果：即使功能都做對了，顧客仍覺得系統「不專業、不可靠」，不敢輸入信用卡或個資。

**正確範例**

- 所有卡片沿同一網格對齊，使用 1–2 種字體（標題字＋內文字），大小與粗細遵守設計系統。
- 色彩使用克制：明確主色、背景色、文字色、強調色，各司其職，不過度裝飾。
- 在付款頁面，使用更穩重的配色與清楚的排版，保持品牌風格但加強安全感。

結果：顧客感覺這是一個正式產品，而不是半成品或學生作業，願意在上面完成重要操作。

---

### 五、錯誤預防與錯誤處理 × 錯誤狀態的風格與文案

**1. UX 原則/方法的目的**

- 目的：在錯誤發生前預防（必填欄位、格式檢查），錯誤發生後提供清楚、具體的訊息與修正路徑。
- 要解決的 UX 問題：降低挫折感、不讓使用者卡死、提升問題可恢復性。

**2. 對應的風格要做什麼**

- 錯誤提示的顏色、圖示、文案口氣、版面配置，要讓使用者覺得「被幫助」而不是「被責備」。
- 在訂單錯誤或欄位漏填時，用清楚且友善的提示，而非一堆巨大紅字警告。

**錯誤範例**

- 使用者忘記選取取餐時間，送出訂單後只跳出小字紅色訊息：「錯誤」。
- 或在畫面上顯示大寫紅字：「你錯了！請輸入正確資料」，沒有指出是哪個欄位。

結果：使用者不知道哪裡錯，只覺得系統在罵人，容易放棄使用，回到人工點餐。

**正確範例**

- 在取餐時間欄位下方顯示友善訊息：「請選取一個取餐時間，讓我們準時為你準備早餐」。
- 該欄位框線用柔和紅色＋明確文字說明，而不是整頁大紅警告。
- 若整體送出失敗，在頁面上方顯示簡短訊息：「訂單尚未送出，請確認以下欄位」，並將錯誤欄位以一致風格標示清楚。

結果：使用者知道自己哪裡沒完成，也知道如何修正；錯誤狀態仍維持整體風格的溫度與專業感，不破壞品牌信任。

- 每一個風格決策，背後都應該有一個 UX 問題在支撐。

## 核心觀念：從抽象風格到設計系統

### 為什麼要教「風格 × AI」？

- 實務工作裡，現在大量開發者用 AI 工具產生功能，但畫面一致性與品牌感往往不足。
- 若學生只會請 AI「幫我做一個漂亮網站」，結果就是典型 AI 模板風格：紫藍漸層、三欄卡片、圓角卡片、抽象背景，而不是專案自己的品牌語言。
- 讓學生理解：
  - **風格是策略，不是裝飾**。
  - **風格要被規格化**，AI 才能穩定生成一致 UI。

### 風格拆解框架（教學用）

你可以用這 8 個維度當課堂模板，讓學生先寫，再交給 AI：

1. 品牌人格。
2. 色彩策略。
3. 字體氣質。
4. 版面密度。
5. 元件語言。
6. 圖像語言。
7. 動態語言。
8. 文案口氣。

這個框架也有助於把服務設計轉譯後的風格結果，整理成 AI 與前端都讀得懂的規格。

### 避免「AI 味」的負面約束清單

兩個工具都容易產生同質化的 AI 模板風格，老師應要求學生在 Prompt 中明確加入「不要」清單：

- 不要紫藍漸層
- 不要過度 SaaS 感
- 不要太像後台 ERP
- 不要抽象背景圖
- 不要三欄卡片制式排版
- 要像「有溫度但有效率的早餐服務」

這類「負面約束」能大幅降低 AI 跑偏的機會。

## 課堂結構：第 3 週完整流程

### 第一段：從 01 服務設計推導風格（60 分鐘）

**使用工具**：紙筆討論＋Claude Artifacts（文字推理）

- 回看 01 輸出：角色、旅程圖、藍圖、需求文件。
- 找出主要情境、主要使用者、主要痛點。
- 用 Claude Artifacts 協助寫出核心體驗目標句。
- 將體驗目標轉成品牌人格。

### 第二段：用 Google Stitch 做大量風格探索（50 分鐘）

**使用工具**：Google Stitch

- 把上一步的品牌人格與服務情境輸入 Google Stitch。
- 每組至少生成 3–5 個風格變體（可用同一份 Prompt 重複生成，或調整方向後再生成）。
- 用 Redesign 功能微調最有潛力的 2–3 個版本。
- 截圖記錄每個版本，標註優缺點。

### 第三段：用 Claude Artifacts 收斂與觀察程式碼（40 分鐘）

**使用工具**：Claude Artifacts

- 從 Google Stitch 的版本中選 1–2 個方向。
- 用 Claude Artifacts 生成可執行的 HTML/CSS/JS 版本。
- 用對話迭代修改（配色、間距、元件）。
- 點擊「View Code」觀察生成的程式碼，標記看得懂與看不懂的部分。
- 討論：這些程式碼如何對應到選定的風格規格？

### 第四段：比較與收斂（20 分鐘）

- 討論哪一版最符合服務。
- 指出哪一版只是好看，但不適合早餐店真實情境。
- 選定最終方向。

### 第五段：輸出規格文件（20 分鐘）

**使用工具**：Claude Artifacts 或 ChatGPT 免費版

- 將結果整理成 `STYLE_GUIDE.md` 或 `DESIGN.md` 初版。
- 為第 4–6 週前端落地做準備。

## 評量規準（補強版）

| 評量面向 | 比重 | 評量重點 |
|---|---:|---|
| 服務到風格的轉譯邏輯 | 30% | 是否能說清楚風格來自角色、情境、痛點與價值主張 |
| 風格一致性 | 25% | 各頁面是否明顯同一品牌、形式統一 |
| 規格完整度 | 20% | 設計系統內容是否涵蓋必要項目 |
| AI 使用素養 | 15% | Prompt 清晰度、負面約束使用、批判性修正、對話紀錄整理 |
| 反思深度 | 10% | 能否說出 AI 做得好／不好，以及自己如何補位 |

## 工具使用注意事項

### Claude Artifacts 額度管理

- 免費版有每日訊息量限制（視複雜度而定），課堂需注意額度管理。
- 建議每組分工：一人負責提問迭代，其他人記錄與討論。
- 較長的服務設計資料可先精簡再貼入，節省訊息量。
- 若額度用盡，可改用 ChatGPT 免費版做文字推理，或用 Google Stitch 做視覺生成。

### Google Stitch 使用技巧

- 結構化指令效果最好：先給品牌人格、再給使用情境、再給視覺方向、最後給「不要」清單。
- 上傳參考圖能大幅提升生成品質。
- Redesign 額度每日只有 15 次，建議先用文字生成多個版本，再挑最好的做 Redesign。
- 生成結果可截圖保存，作為作業附件。

### 程式碼觀察的教學重點

Claude Artifacts 生成的是真實 HTML/CSS/JS，老師應引導學生：

- 觀察 CSS 中的色彩值是否與 DESIGN.md 一致。
- 觀察 HTML 結構如何對應視覺區塊（header、main、section）。
- 標記看得懂與看不懂的程式碼，作為第 4–6 週學習的預習。
- 不要直接把 Artifacts 生成的程式碼當作業提交，要理解後再修改。

## 與下一週的銜接

第 4–6 週的前端基礎，不是重新思考品牌，而是把第 3 週確立的風格規格轉成 HTML、CSS、JavaScript。老師要一直提醒學生：前端實作的目標，不是做出「一個差不多的網站」，而是把由服務設計推導而來的品牌體驗真正落地到畫面與互動之中。

Claude Artifacts 在第 3 週生成的程式碼，可作為第 4–6 週的「參考實作」——學生不是照抄，而是理解後自己重寫，把風格規格真正落地。這也建立了從「AI 生成→人類理解→人類實作」的學習路徑。
