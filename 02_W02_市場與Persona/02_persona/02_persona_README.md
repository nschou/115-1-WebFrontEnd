## 調研方法（從第 2 週講義抽取）

### 步驟 1：價值交換分析

分析「誰付錢、誰決定買、誰實際使用」，找出價值交換的發生點。用 5 問分析：
- 誰付錢？→ 找出收入來源
- 誰決定買？→ 找出決策者
- 誰實際使用？→ 找出體驗主體
- 誰因服務成功而獲得價值？→ 找出核心價值對象
- 企業如何因此獲利？→ 連結商業模式

結論：主要 Persona 是驅動價值交換的那個人。其他角色是為了交付價值而產生的支持系統。

### 步驟 2：老闆 Persona 推導

從 `01_market.md` 的市場選擇和老闆投入意願分析，推導老闆 Persona 的每個欄位：
- 年齡/經驗 → 從市場特徵推導
- 目標 → 從老闆投入意願分析（步驟2）的「期望什麼回報」
- 痛點 → 從行業研究和市場分析
- 期望感受 → 從目標和痛點推導（設計推導）

### 步驟 3：主要顧客 Persona 推導

從 `01_market.md` 的目標客群推導：
- 年齡/職業 → 從市場的目標客群特徵
- 使用情境 → 從市場的服務流程
- 痛點 → 從行業研究的痛點分析
- 期望感受 → 從痛點和目標推導

### 步驟 4：支持系統 Persona 推導

從主要 Persona 的需求推導：
- 需要誰來交付價值？→ 支持角色
- 支持角色的目標 → 確保服務品質和效率
- 支持角色的痛點 → 從營運流程推導

### 步驟 5：角色決定

如有需要決定的角色配置（如廚師由誰擔任），記錄選項、優缺點、選定理由、代價。

## AI 協作（分階段）

### 階段 1：盤點與提問
```
請讀取 @02_persona_rd_template.md 和 @01_market.md。
先盤點已有資料與缺漏，提出本輪需要推導的問題。
不要直接寫成完整 Persona——先確認推導方向。
```

### 階段 2：推導與論述
```
以下是市場結論：[貼入 01_market.md]
請協助推導三層 Persona，填入 02_persona_rd_template.md。
每個欄位標注推導來源。缺少證據的標為待補。不得假造。
```

### 階段 3：整理結論
```
請讀取 @02_persona_rd.md，以 @02_persona_template.md 為範本，
產生 02_persona.md。
```

## 驗收標準
- 三層 Persona 都有完整欄位
- 每個欄位有推導來源
- 主要 Persona 是從價值交換分析確定的
- 角色決定有理由和代價
- 無假造資料
