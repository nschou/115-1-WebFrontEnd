# ADR-006：18 檔主線與週次目錄重建

- **狀態**：Accepted
- **日期**：2026-10-31
- **範圍**：W1–W7 教材、主線文件、示範案例、學生工具包

## 背景

原有文件分散在不同週次與歷史命名中：`05_decisions`、`06_objects`、`10_tasks`、`14_stories`、`15_review`、`16_spec` 等名稱容易讓學生誤判產出順序，也把 review 活動與主線文件混在一起。服務藍圖中的候選方案，必須先逐項選定，才能形成 Blueprint baseline；否則後續 Design、UX 與 spec 可能帶著未決選項前進。

## 決策

採用單一、連續的 18 檔主線：

`01_market` → `02_persona` → `03_cjm` → `04_blueprint` → `05_objects` → `06_infoflow` → `07_decisions` → `08_service-design-baseline` → `09_DESIGN` → `10_tokens.css` → `11_service-requirements` → `12_role-tasks` → `13_UserStory-B` → `14_elements` → `15_UX` → `16_wireframes` → `17_UserStory-I_AC` → `18_spec`

- `07_decisions` 固定承接 Blueprint 選項並完成 SD-01–SD-11。
- `08_service-design-baseline` 是 Design、UX、spec 的服務設計唯一基準。
- `12_role-tasks` 取代模糊的 tasks 命名，保留七格供應側角色任務。
- `review` 改為 `validation/` 驗證活動，不占主線編號。
- US-B 在 UX 之前產出；US-I 在線框與狀態之後產出；兩者與 AC 同檔分節於第 17 檔。
- 每週目錄固定以 `00_Wxx_上課講義`、`簡報`、`教師教學指引`、`學生操作手冊`、`學生工具包` 為入口。
- 舊樹先完整備份與雜湊驗證，再切換新樹。

## 替代方案

1. **沿用舊編號並只補 README**：改動較少，但學生仍會遇到跨週重名、10/14/16 的語意錯置與 review 是否算主線的疑問；不採用。
2. **把 service-requirements、role-tasks、US-B 合併**：檔案較少，但會混淆索引、供應側任務與需求側價值；不採用。
3. **把 US-B、US-I、AC 分成三個主線編號**：追溯更細，但增加教學斷點與編號負擔；本次採用同一第 17 檔的明確分節。
4. **把 review 編入主線**：能強調檢查，但會讓驗證活動看似需求產出，且破壞 `18_spec` 的連續編號；不採用。

## 後果

### 正面

- 學生可依數字順序知道應產出什麼。
- 每一階段都有明確輸入、產出、下游用途與回退點。
- 11 條決策不再被 baseline 或 UX 隱含跳過。
- 新工具包可按週次直接打包，示範案例可逐檔參照。

### 代價

- 舊檔路徑與舊引用不能直接當現行輸入，需更新教材、腳本、示範案例與連結。
- 新舊編號同時存在於歷史封存與新樹，檢查腳本必須排除 `99_歷史封存`。
- W1–W7 的講義、手冊、簡報與工具包需同步維護。

## 驗收

- 新樹存在 18 檔主線且順序唯一。
- `07_decisions` 有 SD-01–SD-11；baseline 不保留未決候選。
- W6 validation 能在 `17_UserStory-I_AC` 前提供檢查證據。
- `18_spec` 能引用 `08`–`17`，不引入技術實作決策。
- 封存 manifest 與備份內容驗證通過。
