# ADR-007：Prototype 操作回饋持續顯示

- **狀態**：Accepted
- **日期**：2026-10-31
- **範圍**：W6 prototype、98 示範案例 prototype

## 背景

`story-runner.js` 原本將動態操作回饋實作成兩種會自動結束的形式：toast 在 350ms 後淡出、700ms 後移除；沒有下一頁或明確狀態的操作面板在處理計時後直接隱藏。`scr-02-menu` 的「＋」按鈕因此在使用者看清楚加入購物車結果前就失去提示；付款失敗與其他操作完成回饋也有相同風險。

## 決策

共用動態回饋改為持續顯示：

- toast 不使用自動淡出或自動移除計時。
- toast 提示內容使用文字節點，避免把回饋字串當 HTML 插入。
- toast 以 `role="status"` 與 `aria-live="polite"` 告知輔助技術。
- toast 提供明確的「關閉」按鈕；只有使用者按下後才移除提示。
- 沒有下一頁或 `applyState` 的操作，處理完成後保留操作面板，將進度訊息改為完成訊息；使用者按面板的「關閉」後才離開。
- 同一時間產生新 toast 時，先移除舊 toast，避免提示互相堆疊。
- 內部跳頁提示仍隨頁面轉換結束；本決策針對留在原頁的操作回饋。

active prototype 與 `98_示範案例/雲端早餐店/` 必須保持相同實作。

## 替代方案

1. **延長固定秒數後自動消失**：仍可能在不同閱讀速度或輔助技術情境下消失；不採用。
2. **只把 `scr-02-menu` 改成頁面內 banner**：能修單一畫面，但共用 runner 的其他操作回饋仍有相同缺陷；不採用。
3. **提示永久保留且沒有關閉控制**：會造成後續內容遮擋，且不符合使用者控制；不採用。

## 後果

### 正面

- 加入購物車、付款失敗與操作完成等重要回饋可讀到完整內容。
- 使用者能明確控制訊息何時消失。
- active prototype 與示範案例行為一致。
- 提示具備可辨識的狀態語意與可操作關閉控制。

### 代價

- 提示會佔用畫面直到關閉，需保留足夠的畫面邊界與關閉按鈕樣式。
- 若連續觸發多個提示，後一個會取代前一個，不保留提示佇列。

## 驗收

- `scr-02-menu` 按下「＋」後，處理計時結束時，完成訊息或面板仍存在。
- toast 或操作面板有可見「關閉」按鈕，按下後才從 DOM／畫面移除。
- active prototype 與示範案例的 `story-runner.js`、`wire.css` 同步。
- W6 四層檢查、DOM smoke check 與負向測試通過。
