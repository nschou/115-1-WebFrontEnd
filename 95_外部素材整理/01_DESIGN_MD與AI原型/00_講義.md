> 整理方式：依影片標題、簡介與兩個工具的官方說明整理；AI 字幕回傳內容與影片不符，未採用（詳見來源摘要）。
> 名詞：DESIGN.md（設計規範文件，描述「長什麼樣」）／design tokens（設計變數，例如顏色與間距）／prototype（原型）。

## 0. 三個問題

1. 對 AI 說「做一個訂單狀態頁」，它為什麼常常畫出一個「看起來像別人家」的頁面？
2. 你要 AI 先知道「做什麼」，還是先知道「長什麼樣」？
3. 新產品還沒有 UI 規範時，DESIGN.md 從哪裡來？

## 1. 問題通常不在提示詞，在缺少設計上下文

| 你給 AI 的 | AI 的處境 | 結果 |
|---|---|---|
| 只有一句需求 | 不知道顏色、字體、間距、元件長相 | 用「平均值」回答，看起來不像你的產品 |
| 需求＋畫面參考圖 | 知道大概長相，但不知道規則 | 接近，但每個元件仍不一致 |
| 需求＋DESIGN.md | 有可套用的規則 | 產出穩定、可檢查 |

> 一句話：**spec 說「做什麼」，DESIGN.md 說「長什麼樣」**。兩份都是 AI 的輸入。

## 2. DESIGN.md 的最小內容

| 類別 | 要寫什麼 | 例子 |
|---|---|---|
| 色彩 | 語意色票與使用規則 | `--color-primary`、surface、on-surface、error |
| 字體 | 字族、大小階層、行高、字重 | 標題 24/32、正文 16/24 |
| 間距 | 基準與常用值 | 4 的倍數：4／8／12／16／24 |
| 形狀 | 圓角、陰影、邊框 | 卡片 12px、按鈕 8px |
| 斷點 | 手機／平板／桌機 | 640／1024／1280 |
| 元件狀態 | default／hover／focus／disabled／error | 按鈕五態、輸入框錯誤態 |
| 可用性 | 對比、焦點可見、不只靠顏色 | 文字對比 ≥ 4.5:1 |
| 禁止 | 不要做什麼 | 不用純色塊當唯一狀態提示 |

> 沒有狀態與斷點的 DESIGN.md，等於只寫了半套。

## 3. 三種來源，三條路

| 情境 | 做法 | 工具 |
|---|---|---|
| **有自己的產品** | 從現有原始碼、截圖或網址提取 | design-generator、designmd.cc |
| **有參考網站** | 貼上網址，提取它的設計規則 | designmd.cc |
| **什麼都沒有** | 先從成熟產品的設計庫找參考 | getdesign.md |

> 決策順序：自己的 → 參考網站 → 設計庫。不要跳過前兩個直接抄品牌。

## 4. 兩個工具

### designmd.cc

| 項目 | 說明 |
|---|---|
| 輸入 | 一個網址 |
| 輸出 | DESIGN.md：色彩 tokens、字體、CSS 變數、間距、斷點、元件 |
| 適用 | 已有產品或已有參考網站 |

### getdesign.md

| 項目 | 說明 |
|---|---|
| 內容 | 60+ 知名品牌的設計系統分析 |
| 用法 | 網站瀏覽，或 CLI：`npx getdesign@latest list`、`npx getdesign@latest add stripe` |
| 適用 | 還沒有設計方向，需要先找參考 |

> 提取與下載都是**參考**，不是複製。品牌色、商標、字型授權都要另外確認。

## 5. 正確順序

```text
需求（做什麼）
  → DESIGN.md（長什麼樣）
    → 規格／驗收條件
      → AI 產原型
        → 對照 DESIGN.md 驗收
```

給 AI 的提示要包含：

1. 附上 DESIGN.md。
2. 指定一個頁面，不要一次要全部。
3. 要求先列出「會用到哪些元件與狀態」，再開始畫。
4. 要求輸出時標明「用了哪幾條 DESIGN.md 規則」。

## 6. 四個經典例子

> 以下數字與顏色是**示例**，用來對照「有規則」與「沒規則」的差別；不是要照抄。

### 例 1：同一頁，兩種輸入

| | 輸入 A | 輸入 B |
|---|---|---|
| 給 AI 的內容 | 「幫我做訂單狀態頁」 | 同一句話＋附 DESIGN.md（主色、字級 16/24、間距 4 的倍數、卡片圓角 12、S6 才顯示取餐號碼、四種狀態） |
| 顏色 | AI 自創 5–7 種藍 | 只會用設計變數裡的 2 種藍 |
| 字級 | 4–6 種，沒有階層 | 固定 3 層（標題／內文／說明） |
| 間距 | 忽大忽小 | 4 的倍數 |
| 狀態 | 只有「正常」 | loading／empty／error／success |
| 手機版 | 常爆版 | 依斷點收合 |

**觀察點**：差別不在提示詞變長，而在**規則變明確**。

### 例 2：從參考網站提取（designmd.cc）

情境：找到一個喜歡的電商後台，想讓自己的專案「有那種節奏」。

| 可以借用 | 不要借用 |
|---|---|
| 間距節奏（8 的倍數） | 品牌色 |
| 字級階層（標題／內文／說明） | Logo 與圖示 |
| 元件的五種狀態 | 有授權問題的字型 |
| 卡片與表格的資訊密度 | 具體文案 |

**觀察點**：提取的是「規則」，不是「別人的品牌」。

### 例 3：從設計庫挑起點（getdesign.md）

情境：0→1，還沒有任何方向。

| 步驟 | 動作 |
|---|---|
| 1 | `npx getdesign@latest list` 看有哪些品牌 |
| 2 | 挑 2–3 個風格接近的（例如工具型產品選極簡、高對比） |
| 3 | `npx getdesign@latest add linear` 下載 |
| 4 | 只留「規則」，把顏色與字型換成自己的 |

**觀察點**：設計庫是「起點」，不是「終點」；抄整套會變成別人的產品。

### 例 4（反例）：沒有 tokens 的 AI 輸出

| 症狀 | 修改後 |
|---|---|
| 7 種藍色 | 2 種：主色＋強調色 |
| 5 種圓角 | 1 種：卡片 12、按鈕 8（兩個角色） |
| 3 套間距 | 1 套：4／8／12／16／24 |
| 狀態只用顏色 | 顏色＋文字＋圖示 |

**觀察點**：先收斂「數量」，再談「好看」。

## 7. 常見錯誤

| 錯誤 | 後果 |
|---|---|
| 只給一句需求 | 產出像「別人家」的頁面 |
| 直接抄品牌色 | 授權與識別問題 |
| DESIGN.md 沒有狀態 | 錯誤、載入、停用都沒設計 |
| 沒有斷點 | 手機版直接爆版 |
| 檔案太長沒有優先級 | AI 抓不到重點 |
| 沒有驗收清單 | 無法判斷「像不像」 |

## 8. 檢查點

1. 寫出「spec」與「DESIGN.md」各回答哪一個問題。
2. 列出一份 DESIGN.md 至少要有哪五類內容。
3. 說出三種來源與對應做法。
4. 指出一個「只靠顏色表達狀態」的錯誤，並提出改法。
5. 對照例 1，寫出「有 DESIGN.md」與「沒有」各會出現什麼差異（至少三項）。
6. 說明例 2 中「可以借用」與「不要借用」的分界。
