# 第 5 週教師教學指引｜物件、資訊流、決策、Baseline、Design

## 輸入與目標

輸入是第 4 週 `04_blueprint.md` 的選項版，以及前面市場、Persona、CJM 的依據。目標是完成 `05_objects.md`、`06_infoflow.md`、`07_decisions.md`、`08_service-design-baseline.md`、`09_DESIGN.md`、`10_tokens.css`。

## 教學順序

1. **物件**：從 Blueprint 對象欄盤點 OBJ，補擁有者、生命週期、涉及角色與觀測者。
2. **資訊流**：對每個物件寫變更事件、誰等待、延遲容忍、一致性與競爭熱點；不寫技術名。
3. **11 條決策**：逐條從 Blueprint 候選中選定 SD-01–SD-11，記採用、理由、代價；`04_blueprint` 的不同選項必須在這裡定案。
4. **Prompt 1／2 與 Baseline**：依 `00_W05_PROMPTS.md` 先產生 `baseline-draft.md`，再整併成 `08_service-design-baseline.md`。
5. **Prompt 3／4 與 Stitch**：依 Prompt 參考檔與 13 項清單產出 `stitch-prompt-final.md`，再進入 Stitch。
6. **Design／tokens**：只引用 baseline、品牌與可用性限制，不反過來改寫服務決策；匯出後依 `09_DESIGN/09_DESIGN_README.md` 整併與審計。

> `00_W05_PROMPTS.md` 是學生可直接使用的 Prompt 參考；不可只口頭說明 Prompt 1～4 而不提供檔案。

## 關鍵提問

- 這是跨角色物件，還是單一欄位？
- 誰在等，等多久？如果沒有等待者，為何需要即時？
- 每條決策的採用理由是否回指 Persona／CJM／Blueprint／物件／資訊流？
- 若移除某一個決策，後面哪一個交接或狀態會失效？
