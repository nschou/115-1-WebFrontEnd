# 02_persona｜三層 Persona

> 本檔把市場選擇轉成「誰有問題、誰決定投資、誰交付服務」。

## 1. 老闆 Persona：王建興

| 欄位 | 內容 |
|---|---|
| 基本資料 | 42 歲，餐飲業 15 年，經營 1 家示範店 |
| 目標 | 12 個月損益兩平、月營收 60 萬、數位點餐占比 50%+ |
| 痛點 | 尖峰漏單、新員工學習曲線長、紙本訂單難以統計 |
| 期望 | 掌控全局、數據驅動成長 |
| 角色 | 投資決策者、菜單／庫存／營收負責人；初期兼任廚師 |
| 限制 | 人力與啟動資金有限，不能把所有問題都交給高成本方案 |

## 2. 主要顧客 Persona：張家豪

| 欄位 | 內容 |
|---|---|
| 基本資料 | 28 歲，科技公司工程師，通勤族 |
| 使用情境 | 07:30–08:30 通勤途中點餐，到店取餐帶走或內用 |
| 目標 | 快速拿到早餐、不遲到 |
| 痛點 | 等待時間不確定、品項太多難找、點餐流程不順 |
| 期望 | 高效、可預期、舒適 |
| 不期望 | 混亂、油膩、等待焦慮 |
| 角色 | 顧客、點餐者、付款者、取餐者 |

## 3. 支持系統 Persona：陳美玲

| 欄位 | 內容 |
|---|---|
| 基本資料 | 35 歲，餐飲業 8 年，管理 1 家門市與 3 名員工 |
| 目標 | 尖峰不漏單、員工快速上手、營收達標 |
| 痛點 | 數位與現場訂單混淆、人力調度困難、培訓耗時 |
| 期望 | 秩序感、安心感、可快速判斷 |
| 角色 | 店長／店員：接單、確認、進度更新、收錢、交付 |

## 4. 角色配置決定

初期由王建興兼任廚師，預計營收穩定後再聘專任廚師。代價是尖峰時段老闆可能成為瓶頸，因此後續 Blueprint 必須明確定義店員、廚師與顧客之間的交接。

## 5. 交接

- 輸入給 `03_cjm.md`：顧客目標、使用情境、痛點、期望／不期望感受。
- 輸入給 `04_blueprint.md`：支持系統角色、責任邊界、營運限制。
- 不在本檔決定：畫面、功能清單、技術方案。
