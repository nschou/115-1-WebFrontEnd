# SCR-05 訂單狀態

| 項目 | 內容 |
|---|---|
| SCR | SCR-05（顧客端，L3） |
| 承接任務 | T5 知道還要等多久、T6 找到櫃位 |
| 承接狀態 | S2–S7 ＋ SX3（通知未送達）／SX4（修改要求） |
| 進入條件 | 訂單已成立（S2 以後） |
| 離開條件 | S7 已取餐後轉為歷史訂單 |

## 六態對照

| 頁面狀態 | 對應訂單狀態 | 顯示重點 | MSG |
|---|---|---|---|
| default | S2／S3 | 訂單號、預計時間、進度條 | MSG-11 |
| loading | — | 骨架屏 | — |
| empty | 無訂單 | 空狀態 ＋ 去點餐 | MSG-12 |
| error | SX3 | 「通知沒送到」＋看板提示 | MSG-13 |
| success | S6 | 取餐號碼、櫃位、開櫃碼 | MSG-14 |
| interrupted | SX4 | 修改要求已送出 | MSG-15 |

## 三條業務規則（這一頁最容易做錯的地方）

1. **S4／S5 不得顯示取餐號碼** — default 態只顯示進度，沒有號碼。
2. **通知權限被拒 → 走 error 的降級說明**，不是默默不通知。
3. **S6 的號碼與開櫃碼必須同時出現**，缺一會讓顧客卡在櫃前。

## 怎麼檢查

| 檢查 | 方法 | 通過標準 |
|---|---|---|
| token 覆蓋 | 搜 `screen.css` 的 `#` 與 `px` | 0 筆（`tokens.css` 除外） |
| 六態可達 | `index.html?state=…` 六個 | 都看得到 |
| 灰階結構 | `?mode=wire` 遮住文字 | 3 秒內找到主 CTA |
| 業務規則 | default 態 | 沒有取餐號碼 |
| 鍵盤 | Tab 走一遍 | 焦點可見、順序合理 |
