# 17_UserStory-I_AC

`13_UserStory-B.md`、`15_UX.md`、`16_wireframes/`、狀態機、業務規則與 validation 結果。

## 為什麼 US-I 不和 US-B 1：1

- `US-B` 也可能由多條 US-I 串接或分支完成；每條 US-I 都要列相同的 US-B 來源 ID，讓讀者看出是先後步驟還是替代路徑。

- `US-B` 的單位是業務意圖：痛點、角色目標或價值成果。
- `US-I` 的單位是可走查的介面路徑：一組 SCR、入口、狀態與完成點。
- 多個 US-B 可以共用同一條路徑，因此 US-I 可能較少。
- 一個 US-B 也可能因成功／失敗、重試、角色或狀態分支而形成多個 US-I。
- 沒有獨立路徑的 US-B 不能刪除，必須標示既有承接路徑、N/A 或回上游澄清。

這是追溯關係，不是編號配對。每條 US-I 都要回指一條或多條 US-B、REQ／任務、SCR、狀態與 AC；每條 US-B 都要有 US-I 或明確的 N/A 結果。數量少不必然是漏寫，數量相同也不代表 1：1。

## 產出

`17_UserStory-I_AC.md` 內含兩個分節：

1. UserStory-I：實際介面路徑、畫面順序、承接任務。
2. Acceptance Criteria：由狀態、例外、資訊流與禁止規則反寫的可驗收條件。

## 檢查點

US-I 必須真的走過線框；每條 AC 指回狀態或業務規則，並標示 auto、manual 或 human 驗證責任。
