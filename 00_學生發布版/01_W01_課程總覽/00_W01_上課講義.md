# 第 1 週：服務設計到 Spec 的完整主線

## 0. 本週定位

本課不是從畫面開始，而是把服務問題逐步收斂成可驗收的 `18_spec.md`。每一週的產出都要能成為下一週的輸入；沒有前一階段的證據，不得直接跳到後段設計。

學生使用順序固定為：先讀講義，再讀操作手冊，接著使用工具包實作；完成自己的產出後執行檢查，確認能交給下一週。示範案例用來理解文件責任與推導方式，不是作業答案。

## 2. 七週課程與產出

### 第 1 週：方法論、證據鏈與檔案規約

- 了解「輸入充分 → 產出明確 → 檢查通過」的學習方式。
- 建立命名、ID、來源定位、版本與修改紀錄規則。
- 先看完整 18 檔主線，再逐週追蹤每個交接。

產出：課程工作區、研究問題、文件索引與個人專案假設。

### 第 2 週：市場與 Persona

- 由研究比較市場，不把品牌印象當證據。
- 產出 `01_market.md`、`02_persona.md`。
- Persona 分成老闆／顧客／支持系統三層，分清痛點、目標、責任與限制。

檢查點：市場選擇有來源與理由；三層角色可被下游使用；未決方案不得偽裝成定案。

### 第 3 週：CJM

- 將 Persona 展開成時間軸。
- 產出 `03_cjm.md`：階段、行動、接觸點、情緒、痛點、機會。
- 找出情緒最低點，將痛點轉成可供 Blueprint 使用的機會。

檢查點：每個痛點有對應機會；每個數位接觸點可交給 Blueprint 展開。

### 第 4 週：Service Blueprint

- 以 CJM 前台接觸點為上游，補出後台角色、支援需求與交接。
- 產出選項版 `04_blueprint.md`；此時允許列候選，不提前替老闆做決定。
- 明確交接條件、失敗情境、可見線與內部互動線。

檢查點：前台每個機會都有後台責任者與支援需求；候選方案可被第 5 週比較。

### 第 5 週：物件、資訊流、11 條決策與 Baseline

- 由 Blueprint 的對象欄建立 `05_objects.md`。
- 由物件變更、等待與競爭建立 `06_infoflow.md`。
- 對 Blueprint 的候選方案逐條完成 `07_decisions.md`（SD-01–SD-11），每條包含採用、理由、代價。
- 以已定案的決策整併 `08_service-design-baseline.md`。
- 再建立 `09_DESIGN.md` 與 `10_tokens.css`，不能讓樣式反過來改寫服務決策。

檢查點：11 條決策完整；baseline 不留未決候選；物件、資訊流、角色與決策沒有矛盾。

### 第 6 週：服務需求、角色任務、US-B、UX、線框與 AC

- 先建立 `11_service-requirements.md` 跨來源索引。
- 以七格格式產出 `12_role-tasks.md`；名稱固定為 role-tasks，避免與後續實作 tasks 混淆。
- 從 CJM 痛點、服務需求與角色任務萃取 `13_UserStory-B.md`。
- 以任務與物件需求建立 `14_elements.md`，再完成 `15_UX.md` 與 `16_wireframes/`。
- 線框走查後，在 `17_UserStory-I_AC.md` 分別寫 US-I 路徑與 AC；AC 必須來自狀態、規則與資訊流，不只從 Story 猜。

檢查點：每個元素能回指任務；每條 US-B 有來源；US-I 有實際路徑；AC 可驗證且列出禁止型規則。

### 第 7 週：Spec

- 以 `08_service-design-baseline.md` 為服務決策基準，以 `15_UX.md`、`16_wireframes/`、`17_UserStory-I_AC.md` 為介面與驗收基準。
- 產出不含技術實作決策的 `18_spec.md`。
- 完成引用、來源、需求、AC、章節一致性與檢查工具驗證。

檢查點：`18_spec.md` 不引入上游未決方案；每條需求有來源與驗收；整條主線可由前往後追溯。

## 3. 證據鏈的共同規約

1. **來源定位**：任何重要理由標出來源檔、章節或 ID；不可只寫「使用者需要」。
2. **ID 不重編**：市場、Persona、CJM、物件、決策、任務、元素、US、AC、SCR 一經建立，後續只新增或標記淘汰。
3. **業務／設計／實作分層**：Blueprint 與 baseline 不寫技術名；`18_spec.md` 不替前段補做未決服務設計。
4. **每階段輸入檢查**：先確認上游檔案存在、內容完整、候選或定案狀態清楚，再開始本階段。
5. **每階段輸出檢查**：列出產出檔、下游使用者、未解問題與驗證證據。
6. **修改紀錄與 ADR**：改流程、編號、責任邊界或重要決策時，必須留下 changelog 與 ADR。

## 4. 本週練習

- 選一個日常服務，畫出 18 檔主線的輸入／輸出箭頭。
- 找一個「看似可以直接做畫面」的需求，說明它缺哪一個上游證據。
- 為自己的專案建立第一版文件清單，不產出沒有來源的 UI。
