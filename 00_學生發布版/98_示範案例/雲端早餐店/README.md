# 雲端早餐店示範案例

## 18 檔主線

`01_market.md` → `02_persona.md` → `03_cjm.md` → `04_blueprint.md` → `05_objects.md` → `06_infoflow.md` → `07_decisions.md` → `08_service-design-baseline.md` → `09_DESIGN.md` → `10_tokens.css` → `11_service-requirements.md` → `12_role-tasks.md` → `13_UserStory-B.md` → `14_elements.md` → `15_UX.md` → `16_wireframes/` → `17_UserStory-I_AC.md` → `18_spec.md`

## 讀法

- `04_blueprint.md` 是選項版；`07_decisions.md` 定案 11 條決策；`08_service-design-baseline.md` 是後續設計的唯一服務設計基準。
- `11_service-requirements.md` 是跨來源索引，不取代 `12_role-tasks.md` 或 `13_UserStory-B.md`。
- `12_role-tasks.md` 是業務角色任務；不要與 Spec Driven Development 的實作 tasks 混用。
- `13_UserStory-B.md` 是需求側價值敘述；`17_UserStory-I_AC.md` 才描述介面路徑與驗收條件。
- `validation/` 是 `16` 與 `17` 之間的強制檢查點，不列為第 19 個主線檔。
- `16_wireframes/00_Prototype整合操作手冊.md` 解釋動態線框的輸入、產生與重跑順序。
- `09_DESIGN_audit.md` 是 Design 的實際審查紀錄；`DESIGN-DISPLAY.md` 是 KDS／看板的遠距顯示契約。
- `validation/review-report.md` 是人工走查證據；Prototype 的 `review-report.js` 與它同步，沒有 `pending` 項目。
