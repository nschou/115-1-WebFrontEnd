# 07_decisions｜11 條服務設計決策

> `04_blueprint.md` 列出選項；本檔由角色目標、CJM 痛點、物件生命週期、資訊流與老闆限制共同定案。每條決策都包含採用、理由與代價，形成 Blueprint baseline 的輸入。

| ID | 決策題 | 採用方案 | 主要依據 | 代價／限制 |
|---|---|---|---|---|
| SD-01 | 訂單接收 | 網頁／行動裝置預點餐＋現場備援 | 通勤顧客要到店前完成；老闆要提高數位占比 | 需維持現場備援與兩種訂單流 |
| SD-02 | 廚房接收 | 店員確認後進入廚房工作佇列 | 避免未付款／未確認訂單直接製作 | 需要店員多一次確認 |
| SD-03 | 進度更新與通知 | 訂單狀態機＋店內看板＋顧客查詢 | 最低點是等待不確定；四端需一致 | 狀態定義與例外處理較複雜 |
| SD-04 | 取餐號碼顯示 | 顧客號碼＋櫃位，店內看板同步 | 顧客不想在櫃前翻手機；號碼需遠距可讀 | 需管理號碼與櫃位回收 |
| SD-05 | 支付 | 行動支付為主，現場付款為備援 | 通勤顧客不想準備零錢 | 付款確認失敗需避免重複扣款 |
| SD-06 | 菜單維護 | 老闆／店長維護供應狀態與圖片內容 | 品項售完要快速同步；顧客需要可判斷資訊 | 內容品質與權限管理需維護 |
| SD-07 | 銷售紀錄 | 每筆訂單結案後留下可查紀錄 | 老闆需知道營收與品項表現 | 需處理取消、退款、現場單 |
| SD-08 | 庫存盤點 | 初期人工盤點＋供應狀態同步 | 人力與資金有限，先解決缺貨造成的錯單 | 尚未完全自動化，需依賴回報 |
| SD-09 | 清潔流程 | 交班檢查表與責任人確認 | 服務不只數位流程，也包含實體交付品質 | 增加交班紀律與檢查成本 |
| SD-10 | 會員經營 | 先保留可識別的回購紀錄，不把會員綁成前置條件 | 先完成核心點餐與取餐，不擴張範圍 | 個人化行銷暫不列入 MVP |
| SD-11 | 經營分析 | 日／週營收與品項彙總 | 老闆需要備料與投資判斷 | 彙總可延遲，不能與即時訂單混用 |

## 定案規則

- Blueprint 中的候選方案不得直接進入 UX 或 spec。
- 任何下游需求若無法回指 SD-01–SD-11、Persona、CJM、物件或資訊流，退回補充依據。
- 本檔完成後，才產出 `08_service-design-baseline.md`；baseline 是後續工程化唯一服務設計基準。
