故事（點「開始走」就在原型裡跑一遍）

故事 × AC 覆蓋矩陣

綠＝有自動檢查（會紅）；灰＝人工檢查；橘＝只能人判斷。

自動檢查結果

由 node verify-stories.mjs 產生；改過畫面要重跑。

動作定義

每個動作都有「意圖／會改什麼／驗收條件」；面板內容由這份資料驅動。

四層檢查

由 node check-all.mjs 一次跑完，結果寫在 assets/checks-summary.js。

兩層證據

規則層（會紅的斷言）自動判定；體驗層（好不好用）只能人做，到 走查台 勾選。

怎麼跑（兩種方式）

方式做什麼會看到
A. 在瀏覽器點上面故事卡的「開始走」，或下表右側的「稽核」頁面上方出現稽核列 → 按「執行檢查」→ PASS／FAIL
B. 在終端機在 prototype/ 資料夾執行下列指令產生報告檔，重新整理本頁就會更新

本頁顯示的是「上一次終端機執行的結果」；要即時驗某一頁，用 A 的稽核模式。

指令

node lint-tokens.mjs        # 版面規範：token／色碼／狀態數
node verify-stories.mjs     # 故事與 AC：結構＋內容
node selftest-stories.mjs   # 負向測試：故意做錯，確認檢查會紅
