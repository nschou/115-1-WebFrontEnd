# 第 3 週學生操作指南：Customer Journey Map

> 本週將 `02_persona.md` 的使用情境展開成顧客旅程，產出 `03_cjm.md`。
> CJM 描述顧客經歷、情緒與痛點；不在本週決定後台技術或完整畫面。

## 1. 本週輸入與輸出

### 必要輸入

- `02_persona.md`
- `03_cjm/03_cjm_rd_template.md`
- `03_cjm/03_cjm_template.md`
- W2 的 `02_persona_rd.md`（只在需要回查推導來源時使用）

### 輸出鏈

```text
02_persona.md
  ↓
03_cjm/03_cjm_rd_template.md
  ↓ 填寫後另存
03_cjm_rd.md
  ↓ 依固定格式整理
03_cjm.md
```

## 2. 先選定旅程主角與範圍

在 `03_cjm_rd.md` 開始前，先寫一段範圍聲明：

```markdown
- 旅程主角：02_persona.md 的哪一個 Persona
- 旅程起點：他開始有需求的具體時刻
- 旅程終點：他認定需求已被滿足的具體時刻
- 不包含：本次不研究的後續服務
- 依據：02_persona.md 的章節或表格位置
```

只能選一個主要顧客旅程。店員、廚師或設施的後台工作會在 W4 Blueprint 展開，不能把多個角色的流程混成同一條 CJM。

## 3. Step 1：推導起點與終點

在 `03_cjm_rd_template.md` A 節回答四題：

1. 顧客從哪裡開始？
2. 為什麼從這裡開始？
3. 顧客到哪裡認定完成？
4. 為什麼在這裡結束？

起點要是顧客開始面對需求的時刻，例如「決定要吃早餐」，不是「打開某個頁面」。終點要是價值已交付的時刻，例如「拿到餐點並知道訂單完成」，不是「按下送出」。

## 4. Step 2：劃分 3–5 個旅程階段

每一階段代表顧客正在完成的一件事，不代表一個畫面。使用下表先草擬：

| 階段 | 顧客想完成什麼 | 顧客實際行動 | 接觸點 | 為什麼獨立成階段 |
|---|---|---|---|---|
| J-01 | | | | |
| J-02 | | | | |
| J-03 | | | | |
| J-04 | | | | |
| J-05 | | | | |

階段切換的判準：顧客目標、行動、情境或等待狀態發生明顯改變。不要依照「我想做幾個頁面」切階段。

## 5. Step 3：填寫每階段的六欄

在 `03_cjm_rd.md` B–E 節填寫：

1. **階段**：使用動詞或清楚的目標名稱。
2. **行動**：顧客做什麼，不寫系統做什麼。
3. **接觸點**：顧客透過什麼與服務接觸，並分類為數位、實體或人際。
4. **情緒**：以 `+3` 到 `-3` 做教學推估，並寫推導來源。
5. **痛點**：顧客在哪裡卡住、等待、害怕或做錯決定。
6. **改善方向／機會**：服務應改善什麼，以及會影響哪個下游文件。

情緒分數不是測量結果。沒有使用者研究時，必須寫：`教學推估：根據 Persona 的不期望感受推導`。

## 6. Step 4：找出最低點並轉成機會

最低點不是「分數最低」就結束。請完成以下因果句：

```text
階段：
顧客行動：
發生什麼阻礙：
顧客因此不能完成什麼：
需要的改善方向：
W4 Blueprint 要追問的後台責任：
```

每個痛點至少對應一個機會。機會要描述改善方向，例如「讓顧客知道何時可以取餐」，不能直接寫成「做一個進度條」，因為元件要到 W6 才決定。

## 7. Step 5：建立數位接觸點清單

在 `03_cjm.md` 第 3 節整理所有數位接觸點：

| ID | 數位接觸點 | 對應階段 | 顧客目的 | 目前痛點／機會 | 是否交給 W4 |
|---|---|---|---|---|---|
| CP-01 | | | | | 是／否 |

判斷「交給 W4」的標準：這個接觸點是否需要服務角色做事、需要交接、需要支援或會產生例外。若只是背景資訊，仍要說明為什麼不交給 Blueprint。

## 8. Step 6：補上物件與資訊需求

使用範本第 5 節：

| 階段 | 接觸點 | 涉及物件 | 顧客需要看到的資訊 | 缺少會怎樣 |
|---|---|---|---|---|
| | | | | |

這裡只寫顧客需要看到什麼，不建立完整物件生命週期。完整物件模型在 W5；本表是讓 W4、W5 知道哪些資訊不能遺漏的輸入。

## 9. AI 協作 Prompt

### Prompt A：盤點

```text
請讀取 @02_persona.md 與 @03_cjm_rd_template.md。
先盤點主要顧客 Persona 的使用情境、目標、痛點、期望感受與不期望感受。
提出旅程起點、終點、3–5 個階段及每階段需要補證據的問題。
不要產生完整 CJM，也不要加入畫面或技術方案。
```

### Prompt B：推導研究工作表

```text
請根據 @02_persona.md，填寫 @03_cjm_rd_template.md。
每階段要有顧客行動、數位／實體／人際接觸點、情緒分數、推導依據、痛點、改善方向與下游影響。
情緒分數標記為「教學推估」；沒有來源的內容標記「待補證據」；不得假造訪談結果。
```

### Prompt C：整理結論

```text
請讀取 @03_cjm_rd.md，並以 @03_cjm_template.md 產生 03_cjm.md。
保留 3–5 個旅程階段、六欄 CJM、情緒曲線、最低點、數位接觸點清單、CJM→下游影響摘要，以及涉及物件與資訊需求。
不要把改善方向改寫成畫面、按鈕、API 或技術方案。
```

## 10. 交付前檢查

- [ ] 主角、起點、終點與來源明確。
- [ ] 有 3–5 個階段，每階段都是顧客行動，不是頁面名稱。
- [ ] 每階段都有行動、接觸點、情緒、痛點與改善方向。
- [ ] 每個情緒分數都有推導依據，且標記教學推估或使用者研究。
- [ ] 最低情緒點有明確理由與優先改善方向。
- [ ] 每個痛點至少有一個機會。
- [ ] 數位接觸點已分類並標明是否交給 W4。
- [ ] 涉及物件與資訊需求已填，沒有把物件規格寫成 UI。
- [ ] 沒有寫後台角色的完整工作流程；那是 W4 的輸入問題。

## 11. 交給 W4 的輸入

```text
03_cjm.md
```

W4 會使用：

- 前台行動
- 數位／實體／人際接觸點
- 每個痛點與機會
- 最低情緒點
- 需要顧客看到的資訊
- 交給 Blueprint 追問的下游影響
